01先抓住文章的核心思路

这篇文章里的后坐力，是一套由时间曲线驱动的相机旋转系统。它不要求先模拟枪械质量、枪口动量或肩部受力，而是直接指定镜头在开火后的不同时间应该偏转多少。这样，设计者可以独立调整“抬得多高”“冲击多快”“回弹多少”“停多久”“恢复多慢”。

开火事件→选本枪后坐力数据→推进时间 / 阶段→采样曲线→计算 Pitch/Yaw 差值→更新相机 + Roll

最关键的区别是：曲线返回的“偏移值”，与相机接口需要的“本帧旋转增量”，不是一回事。原文的 Pitch/Yaw 通过差分转换后再应用，Roll 则把采样结果直接当作当前 Roll 值。

原文事实文章展示了上抬函数、时间修正调用、Roll 震动函数和参数定义，但没有提供完整的回弹、下降、连射回正、鼠标补偿实现。

补充说明本文给出的完整控制流程、边界处理和示例曲线，是为理解与落地而补充的实现示例。不能把它们当作原作者未展示的源代码。

文章标题覆盖整个相机系统，所以最后也解释状态机、呼吸晃动和骨骼跟随代码。它们和后坐力有一个共同问题：多个来源怎样同时影响相机，而不重复累加或互相覆盖。

02Pitch、Yaw、Roll 各自负责什么

轴看到的变化后坐力中的作用原文应用方式
Pitch · 俯仰视线向上 / 向下主要体现开枪上抬，以及后续回落每步应用相对上步的差值
Yaw · 偏航视线向左 / 向右体现横向偏转、弹序方向变化每步应用相对上步的差值
Roll · 滚转画面绕视线倾斜，地平线左右歪体现冲击、震动和释放过程使用当前采样值，而非再次累加

为方便阅读，本文把“向上抬”记为正 Pitch。实际引擎的 Pitch 正方向可能相反，最终要在相机接口处统一符号。原文参数说明中，Yaw/Pitch 数据标为弧度；下文数值演示使用度，只是方便直觉理解。

度 = 弧度 × 180 / π
例如：0.02 rad ≈ 1.146°

相机后坐力是否直接改变弹道，需要看项目的瞄准与射线系统。原文没有说明“子弹方向是否取最终相机方向”，因此不能仅凭这份文章认定 Pitch/Yaw 必然影响命中点，或者 Roll 必然只用于表现。

03单发后坐力为何拆成四个阶段

t0 · 上抬从 0 快速升到峰值。
t1 · 瞬时回弹从峰值掉回一部分。
t2 · 稳定短暂维持回弹后的高度。
t3 · 下降把剩余偏移恢复到 0。

3.1 上抬：表现开火冲击

假设这枪 Pitch 峰值是 2°，上抬时间是 0.06 秒。镜头从后坐力偏移 0°，沿曲线升到 2°。如果是线性曲线，时间过半就抬到 1°；如果是“先快后慢”，一开始就会抬起较多，接近峰值时减速。

Pitch 和 Yaw 使用同一个进度采样，但各自的目标幅度可以不同，例如 Pitch 为 +2°，Yaw 为 −0.4°。原文的 RecoilUp() 就负责这个过程。

3.2 瞬时回弹：从峰值退回稳定值

RecoilFallPct 的原文注释是“后座稳定前回弹至百分比”。结合图形，合理理解是回弹后的剩余幅度占峰值的比例。例如取 0.65，峰值 2° 回弹后剩 1.3°，本次回弹的变化量为 −0.7°。

稳定偏移 = 峰值偏移 × FallPct
回弹增量 = 稳定偏移 − 峰值偏移 = 峰值偏移 × (FallPct − 1)

这里是根据参数注释做出的解释。原文没有展示实际乘法，不能完全排除项目把它定义成“回弹掉的比例”。接入已有代码时，应确认它实际表达的是“剩余 65%”，还是“退回 65%”。本文示例统一采用剩余比例。

原图回弹段是短斜线，并非完全竖直；原文称它“瞬时”。参数列表又没有独立的回弹时长。因此可以确定存在这段表现，但不能确定它究竟是一个更新步内跳变，还是一个极短的插值过程。本文补全示例将它视为阶段交界处的一次瞬时变化。

3.3 稳定：保持剩余偏移

镜头在 1.3° 的后坐力偏移处保持一小段时间。对于增量相机接口，这时应传 0°，因为目标没有变化。若每步都传 1.3°，镜头会继续抬升，平台阶段就变成了持续爬升。

3.4 下降：释放剩余偏移

剩余 1.3° 沿下降曲线恢复到 0°。这段通常比上抬更舒缓，但具体时长与曲线属于调参选择。它回收的是系统自己施加的后坐力偏移；是否还要回到开枪前的世界朝向，则是额外设计问题，后文单独说明。

3.5 原文阶段编号有一处不一致

原文正文参数列表注释本文统一称法
t0 上抬RecoilUpTime：t0上抬时长 T_up
t1 瞬时回弹没有独立回弹时间字段回弹事件 / 可选短回弹段
t2 稳定RecoilStaticTime：t1稳定时长 T_hold
t3 下降RecoilDownTime：t2下降时长 T_down

因此读代码时，应按变量语义理解，而不是把注释中的 t1/t2 与正文编号直接一一对应。若回弹是瞬时事件，总时间可以写成 T_up + T_hold + T_down；若回弹有独立时长，就还要加上 T_fall。

04为什么必须计算“本帧增量”

原文说，FpsPlacer 对 Pitch/Yaw 的 Rotate 操作接收的是“本帧相对上一帧的变化值”。因此调用的含义接近 pitch += deltaPitch，而不是 pitch = targetPitch。

假设一段上抬曲线，连续三步采样得到 0.5°、1.2°、2.0°。这三个数表示在相应时刻，这一枪累计贡献的后坐力偏移应该是多少。

更新步曲线当前偏移正确传入增量正确累计结果误把偏移直接累加
10.5°0.5 − 0 = 0.5°0.5°0.5°
21.2°1.2 − 0.5 = 0.7°1.2°1.7°
32.0°2.0 − 1.2 = 0.8°2.0°3.7°
q(t) = 曲线定义的后坐力偏移
Δqₙ = q(tₙ) − q(tₙ₋₁)
相机每步旋转 Δqₙ

差值累加时，中间项会相互抵消：(q₁−q₀)+(q₂−q₁)+…+(qₙ−qₙ₋₁)=qₙ−q₀。所以，只要从同一条曲线正确计算差分、不漏末尾，也没有角度限幅等干预，最终累计偏移由曲线端点决定，不会因为采样步数多就越来越大。

一个特别容易混淆的变量

self.recoilPitch 应当保存上一更新步的后坐力曲线偏移，不是整个相机的 Pitch。整个相机还有玩家鼠标输入、呼吸、动画等贡献。如果拿完整相机角度来做相减，就把别的来源也混进后坐力了。

牢记这三层：曲线偏移 q 是目标；本步差值 Δq 是增量接口的输入；相机最终朝向 是多个来源合成的结果。

05RecoilUp 逐行解释

原文代码下面保留原文函数：

def RecoilUp(self):
    # 计算此次 tick 需要上抬至的幅度
    recoilPitch = Lerp(0, self.RecoilPitchRange,
                       self.recoil_time / self.RecoilUpTime,
                       self.RecoilUpEasing)
    recoilYaw = Lerp(0, self.RecoilYawRange,
                     self.recoil_time / self.RecoilUpTime,
                     self.RecoilUpEasing)

    # 相对上一次采样的增量
    diffRecoilPitch = recoilPitch - self.recoilPitch
    diffRecoilYaw = recoilYaw - self.recoilYaw

    return recoilPitch, recoilYaw, diffRecoilPitch, diffRecoilYaw

5.1 Lerp 的四个参数

标准线性插值常见写法只有三个参数；这里多出来的 RecoilUpEasing，说明原文使用的是带缓动曲线的自定义插值函数。按它的用途，可以理解为：

# 补充：对原文 Lerp 用法的语义展开
u = Clamp(elapsed / duration, 0, 1)
w = Ease(u)                  # 把时间进度转换成曲线进度
value = start + (end - start) * w
参数这里的值意思
start0这一枪的局部上抬从零偏移开始
endRecoilPitchRange / RecoilYawRange本次上抬的目标峰值
urecoil_time / RecoilUpTime已消耗时长占整个上抬时长的比例
easingRecoilUpEasing时间进度到幅度进度的映射

如果峰值为 2°，时长为 0.06 秒，当前经过 0.03 秒，则 u=0.5。线性缓动 E(u)=u 会得到 1°；若用示例缓动 E(u)=1−(1−u)³，会得到 1.75°，因为它前快后慢。这里的具体缓动公式是讲解示例，原文没有列出 EasingType 的实现。

5.2 两个 diff 才是要传给 Rotate 的值

第一行计算的是“现在应该达到多少”，下面相减计算的是“从上一更新步到现在，应该再转多少”。Yaw 为负也没有问题：从 0 到 −0.1 的差值是 −0.1，再到 −0.3 的差值是 −0.2。

5.3 四个返回值分别给谁使用

前两个返回值用于更新历史采样；后两个用于旋转相机。函数本身没有把 self.recoilPitch 和 self.recoilYaw 写回，所以调用者必须补上这一步。

# 补充：原文未展示的必要调用流程
pitch, yaw, deltaPitch, deltaYaw = self.RecoilUp()

# 此处 Rotate 是接口语义示意，参数顺序以实际引擎为准
camera.Rotate(deltaPitch=deltaPitch, deltaYaw=deltaYaw)

self.recoilPitch = pitch     # 必须记住本次采样
self.recoilYaw = yaw

如果忘了写回，旧值一直是 0，就会再次把完整偏移当增量叠加。另一个错误是先把历史值更新，再相减：那样差值永远是 0。

5.4 回弹与下降也必须沿用同样的差分规则

# 补充：下降阶段示例
u = Clamp(downElapsed / downDuration, 0, 1)
pitch = Lerp(stablePitch, 0, u, downEasing)
yaw   = Lerp(stableYaw,   0, u, downEasing)

deltaPitch = pitch - previousPitch
deltaYaw   = yaw   - previousYaw

camera.Rotate(deltaPitch=deltaPitch, deltaYaw=deltaYaw)
previousPitch, previousYaw = pitch, yaw

下降段通常产生负 Pitch 增量，但这是相减自然得到的结果，不需要额外手动再加负号。稳定段 pitch=previousPitch 时，增量自然为 0。

06时间修正：为什么曲线必须走到终点

6.1 原文遇到的问题

按文章举例，每步加 0.016 秒，上抬持续 0.06 秒。采样时间依次为 0.016、0.032、0.048、0.064 秒。第三步没有到终点，第四步已经跨过去了。

如果代码只在 time <= 0.06 时调用上抬函数，那么第四步会直接离开上抬段，曲线从未采样 u=1。以线性、2°峰值为例，第三步只到 2×0.048/0.06=1.6°，上抬少了 0.4°。

步未修正时间线性进度线性目标末步修正
10.016 s0.26670.5333°正常采样
20.032 s0.53331.0667°正常采样
30.048 s0.80001.6000°正常采样
40.064 s1.0667可能跳过或越界用 0.060 s 采样，达到 2.0000°

原文代码

self.FixRecoilTime()
if self.recoil_time <= self.RecoilUpTime:
    recoilPitch, recoilYaw, diffRecoilPitch, diffRecoilYaw = self.RecoilUp()

这两行的意图，是先修正跨过端点的时间，再完成本阶段采样。原文没有展示 FixRecoilTime() 函数，因此只能确认作者要求“终点必须被算到”，不能确认内部如何保存剩余时间或切换阶段。

6.2 不能把时间永久锁死在端点

若每步都做 time=min(time,T_up)，又继续用 time<=T_up 判断上抬，就可能一直留在上抬状态。正确方案还必须明确：端点采样完成后，本阶段结束，进入下个阶段。

“钳制插值进度到 0～1”和“修正阶段状态”是两个问题。Clamp(u,0,1) 能防止插值越界，但如果整个采样调用已被阶段条件跳过，它无法补回漏掉的端点。

6.3 精确 60 Hz 的步长是 1/60

原文用 0.016 秒描述稳定 60 帧更新，但数学上 1/60≈0.0166667 秒。0.016 秒实际对应 62.5 Hz。若一秒实际调用 60 次而每次只累计 0.016，逻辑时间只前进 0.96 秒。

因此，解释原文的 0.048/0.064 示例时，应保留它的数值；真正实现时，建议使用引擎提供的固定步长，或明确使用 1.0/60.0。精确 60 Hz 下，0.06 秒阶段的第四步到 0.0666667 秒，仍有同样的跨端点问题。

6.4 更完整的做法：用剩余时间推进后续阶段

补充实现建议第四步只需 0.01 秒就能把 0.05 秒推进到 0.06 秒。当前步长为 1/60 秒，则还剩约 0.0066667 秒，可以进入稳定段继续使用。这样既采样终点，也不丢掉真实经过的时间。

# 阶段推进的核心思想
remaining = fixedDt
while remaining > 0 and recoilIsActive:
    consumed = min(remaining, phaseDuration - phaseElapsed)
    phaseElapsed += consumed
    remaining -= consumed

    SampleAndApplyCurrentPhase()  # 包含 u=1 的端点

    if phaseElapsed >= phaseDuration:
        EnterNextPhase()          # 下个阶段接着消耗 remaining

还要单独处理时长为 0 的阶段：直接采样终点并切换，不能做除法，也不能在循环中永远消耗 0 秒。完整示例会覆盖这一点。

6.5 固定更新能保证什么，不能保证什么

固定步长使曲线的逻辑采样不直接随渲染帧率变化，但还依赖引擎是否真正按固定时间推进、掉帧时是否补步，以及输入和开火事件如何进入逻辑更新。它并不自动保证低渲染帧率下画面同样平滑。

0.05 秒上抬，在 60 Hz 下只有约 3 步。即使终点准确，曲线形状仍可能看起来较离散。需要更顺滑的视觉时，可以在渲染层插值前后两个逻辑状态；插值后的目标再和上次已呈现目标做差，不能把同一个逻辑增量每个渲染帧重复施加。

08Roll：用“衰减包络 × 余弦”做震动

原文代码

# DampingCurveSimulator Tick
def Tick(self, damp_time):
    self.damp_time = damp_time
    a = Lerp(self.amplitude, self.endValue,
             self.damp_time / self.duration, self.easing)
    b = math.cos(2 * math.pi / self.period * self.damp_time
                 + random.uniform(-self.phase, self.phase))
    return a * b

8.1 damp_time 是累计时间，不是每步 dt

函数直接把传入值赋给 self.damp_time，里面没有累加。因此按这个接口，调用者应该传“震动开始后已经经过多久”。如果每步都传相同的 0.016，曲线的时间位置不会正常前进。

8.2 a：控制震动还能摆多大

a 从初始振幅 amplitude 插值到 endValue。它是包络。若振幅为 0.8°、结束为 0°、时长 0.2 秒、采用线性衰减，过 0.1 秒后包络是 0.4°。

原图看起来像常见阻尼衰减，但原代码没有明确使用 exp(-λt)。因此这里是用可调插值曲线做出的衰减震动，是否指数衰减取决于 easing 的具体定义。

8.3 b：控制往哪一侧摆

b(t) = cos(2πt / P + φ)
Roll(t) = A(t) × b(t)
P：周期（秒）　φ：相位（弧度）　A(t)：当前包络振幅

一个完整周期会经历正峰、零、负峰、零，再回到正峰。P 越小，摆动越快。例如 0.1 秒一个周期就是 10 Hz；周期 0.05 秒就是 20 Hz。period 必须大于 0。

相位决定震动从哪个位置开始。固定 φ=0 时，cos(0)=1，初始就处于正向最大倾斜；φ=π/2 时，初始接近 0。要不要开火瞬间出现 Roll 跳变，是表现选择。

8.4 原文每一步都会重新抽随机相位

random.uniform(...) 写在 Tick 里，所以每次调用都抽新的随机数。这并非“开火时抽一个固定相位，再平滑振荡”，而是在振荡位置上逐步加入随机扰动。当 phase 很大时，相邻采样值会明显跳动，可能表现为噪声。

可选改法若想保留每枪差异，同时保持单枪曲线连续，可在开火时抽一次相位：

def OnFire(self):
    self.elapsed = 0
    self.shotPhase = random.uniform(-self.phase, self.phase)

def Tick(self, elapsed):
    u = Clamp(elapsed / self.duration, 0, 1)
    envelope = Lerp(self.amplitude, self.endValue, u, self.easing)
    wave = cos(2 * PI * elapsed / self.period + self.shotPhase)
    return envelope * wave

这是修改建议，不是原文做法。需要可重复回放时，还应管理随机种子或记录每枪随机结果；固定时间步本身不会消除随机差异。

8.5 为什么 Roll 不做同样的增量叠加

假设连续 Roll 采样值是 0.8°、0.2°、−0.4°。原文要求当前倾斜依次就是这三个值。如果把它们都加到旧 Roll 上，结果会成为 0.8°、1.0°、0.6°，不再是设计的往复震动。

# 对应原文“当前 Roll 值”的应用语义
recoilRollOffset = damping.Tick(elapsed)
cameraRoll = baseRoll + recoilRollOffset + otherRollOffsets

若相机底层只有增量旋转接口，也可以用 newRoll−previousRoll 转换；那是接口适配，曲线仍然描述当前偏移。多个 Roll 来源共存时，应先合成各自当前偏移，不能让后坐力直接覆盖骨骼或其他镜头效果。

8.6 结束时需要明确归零

当 endValue=0 且进度被钳制，终点输出为 0。若 endValue≠0 且继续推进余弦，则震动包络不会消失；若到时强制把结果设为 0，又可能发生跳变。所以要明确结束策略、终点采样和退出时的清理。

09“无限状态机”其实是在管理可并存的效果

原文要解决的是：后坐力正在运行时，FOV 开镜变化也可能运行，呼吸晃动也可能存在。传统“同一时刻仅一个当前状态”的写法不方便，因此作者改成维护一个活动状态列表。

文章的“无限状态机”是形象叫法，不表示数学意义上拥有无限状态。从展示的结构看，更接近“可同时激活多个镜头模式的管理器”。

原文代码

def FSMAppend(self, state, *args, **kwargs):
    if isinstance(state, type):
        state = state.NAME

    if state in self.insert_state:
        exitFunc = self.FSMGetHandler(state, 'Exit')
        exitFunc and exitFunc()
        self.insert_state.remove(state)

    self.insert_state.append(state)

    enterFunc = self.FSMGetHandler(state, 'Enter')
    enterFunc and enterFunc(*args, **kwargs)

def FSMRemove(self, state):
    if isinstance(state, type):
        state = state.NAME

    exitFunc = self.FSMGetHandler(state, 'Exit')
    exitFunc and exitFunc()
    self.insert_state.remove(state)

9.1 FSMAppend 的执行顺序

  1. isinstance(state,type) 检查传入的是不是类对象。若传的是类，就取该类的 NAME，统一转成状态标识。
  2. 如果列表里已存在相同状态，先找到并调用 Exit，再把旧列表项删掉。
  3. 将状态名放到活动列表末尾。
  4. 找到并调用 Enter，并把这次传来的参数转交给它。

因此，重复 Append 同一状态不是忽略调用，而是退出后重新进入。开枪时再次追加后坐力状态，可能会重启它的生命周期。但旧后坐力如何继承、残留偏移如何处理，要看没有展示的 Enter/Exit 逻辑。

9.2 几个 Python 写法

写法含义
*args收集额外位置参数，例如这次开火的弹序、强度。
**kwargs收集额外关键字参数，例如 ads=True。
FSMGetHandler(state,'Enter')按状态名寻找入口函数；具体查找方式未展示。
enterFunc and enterFunc(...)短路求值：有函数才调用。更直白的写法是 if enterFunc: enterFunc(...)。

9.3 FSMRemove 隐含了一个前提

它先调用 Exit，再执行 list.remove。若该状态不存在，Python 的 remove 会抛出 ValueError。工程上可以先检查成员关系，使 Remove 可以安全重复调用。还要避免在遍历活动列表时直接删除元素造成跳项；常见做法是遍历快照，或延后处理增删队列。

9.4 PhysicsPostTick 的绑定意味着什么

genv.player.space.world.PhysicsSpace.BindEvent(
    "PhysicsPostTick", self.OnPhysicsTick)

这行把 OnPhysicsTick 注册到物理更新后的事件里。按文章描述，作者的引擎在这里使用稳定 60 Hz 的逻辑更新。事件名本身并不保证所有引擎都是 60 Hz，具体频率与补步行为应以目标项目为准。

文章未展示 Tick 遍历方式。一个清晰的补充结构是：先更新所有活动效果各自的输出，再统一合成 Pitch/Yaw 增量、Roll 偏移与 FOV 当前值，最后操作相机。这样多个模块不会反复读写同一个最终相机值。

11把缺失流程补齐：完整单发参考伪代码

补充示例 · 非原文源码以下保持文章“曲线目标 → 差分 → 增量旋转”的思路。例子支持上抬、瞬时回弹、稳定、下降，保留跨阶段剩余时间，结束时确保归零。

范围明确：这是单发流程示例，只允许上一枪结束后再开始下一枪。连射需要额外选择累积策略，不能把这个限制直接删掉、每枪盲目归零。函数中的 emitDelta(pitch,yaw) 是对引擎相机接口的适配回调，内部所有角度采用同一单位。

def Clamp01(x):
    return max(0.0, min(1.0, x))

def EaseOutCubic(u):
    u = Clamp01(u)
    return 1.0 - (1.0 - u) ** 3

def Lerp(a, b, u, easing):
    return a + (b - a) * easing(Clamp01(u))


class SingleShotRecoil:
    def __init__(self, emitDelta):
        self.emitDelta = emitDelta
        self.phase = "IDLE"
        self.elapsed = 0.0          # 当前阶段的局部时间
        self.previous = (0.0, 0.0) # 只存后坐力曲线偏移

    def Fire(self, peakPitch, peakYaw,
             upTime, holdTime, downTime, fallPct,
             upEasing=EaseOutCubic, downEasing=EaseOutCubic):
        if self.phase != "IDLE":
            raise RuntimeError("本例仅支持无重叠的单发")
        if min(upTime, holdTime, downTime) < 0:
            raise ValueError("阶段时长不能为负")
        if not 0.0 <= fallPct <= 1.0:
            raise ValueError("本例的剩余比例必须在 0～1 内")

        self.peak = (peakPitch, peakYaw)
        self.stable = (peakPitch * fallPct, peakYaw * fallPct)
        self.upTime = upTime
        self.holdTime = holdTime
        self.downTime = downTime
        self.upEasing = upEasing
        self.downEasing = downEasing
        self.previous = (0.0, 0.0)
        self.elapsed = 0.0
        self.phase = "UP"

    def SetOffset(self, pitch, yaw):
        oldPitch, oldYaw = self.previous
        self.emitDelta(pitch - oldPitch, yaw - oldYaw)
        self.previous = (pitch, yaw)

    def PhaseDuration(self):
        return {"UP": self.upTime,
                "HOLD": self.holdTime,
                "DOWN": self.downTime}[self.phase]

    def Sample(self, u):
        if self.phase == "UP":
            self.SetOffset(
                Lerp(0.0, self.peak[0], u, self.upEasing),
                Lerp(0.0, self.peak[1], u, self.upEasing))
        elif self.phase == "HOLD":
            self.SetOffset(*self.stable)  # 保持值不变，差分为 0
        elif self.phase == "DOWN":
            self.SetOffset(
                Lerp(self.stable[0], 0.0, u, self.downEasing),
                Lerp(self.stable[1], 0.0, u, self.downEasing))

    def FinishPhase(self):
        # 切换前确保当前阶段的精确端点已应用。
        if self.phase == "UP":
            self.SetOffset(*self.peak)
            self.SetOffset(*self.stable)  # 瞬时回弹事件
            self.phase = "HOLD"
        elif self.phase == "HOLD":
            self.SetOffset(*self.stable)
            self.phase = "DOWN"
        elif self.phase == "DOWN":
            self.SetOffset(0.0, 0.0)      # 回收末尾残留
            self.phase = "IDLE"
        self.elapsed = 0.0

    def Tick(self, fixedDt):
        if fixedDt < 0:
            raise ValueError("dt 不能为负")
        remaining = fixedDt

        while self.phase != "IDLE":
            duration = self.PhaseDuration()

            # 零时长阶段直接完成，避免除零 / 死循环。
            if duration == 0.0:
                self.Sample(1.0)
                self.FinishPhase()
                continue

            if remaining <= 0.0:
                break

            timeToEnd = max(0.0, duration - self.elapsed)
            consumed = min(remaining, timeToEnd)
            self.elapsed += consumed
            remaining -= consumed
            finished = consumed >= timeToEnd

            # 终点显式使用 u=1，避免数值误差漏端点。
            u = 1.0 if finished else self.elapsed / duration
            self.Sample(u)

            if finished:
                self.FinishPhase()
                # 同一步内继续推进下个阶段，不丢剩余时间。

    def CancelAndClear(self):
        # 本例采用“立即回收本效果偏移”的取消策略。
        self.SetOffset(0.0, 0.0)
        self.phase = "IDLE"
        self.elapsed = 0.0


# 引擎适配示意：确认真实接口的符号、顺序和单位。
def ApplyRecoilDelta(deltaPitch, deltaYaw):
    camera.Rotate(deltaPitch=deltaPitch, deltaYaw=deltaYaw)

recoil = SingleShotRecoil(ApplyRecoilDelta)
recoil.Fire(peakPitch=2.0, peakYaw=-0.4,
            upTime=0.06, holdTime=0.08,
            downTime=0.24, fallPct=0.65)

# 若接口使用弧度，上述 2.0 / -0.4 度需先换成弧度。
def OnPhysicsTick(engineFixedDt):
    recoil.Tick(engineFixedDt)

11.1 为什么在一次 Tick 里可能转相机两次以上

例如跨过上抬终点时，先应用峰值差分，再应用回弹差分，之后还可能进入稳定或下降。若引擎允许顺序增量应用，这样能明确保证逻辑端点；如果采用统一合成，也可收集这些差分后在本步合并应用。

但逻辑上经过峰值，不保证屏幕渲染一定显示这个峰值。若上抬终点和回弹发生在同一个固定步中，渲染可能只看到回弹后的最终值。想让峰值被清楚看见，可以配置有时长的回弹阶段、更合适的上抬时长或渲染采样策略。

11.2 为什么不能在退出时只把 previous 设成 0

如果镜头还有 0.1° 的后坐力残留，直接把历史变量清零只是“忘记了残留”，并未把镜头转回去。本例先 SetOffset(0,0) 发出最后一个负差值，再清理状态。这也是切枪、关闭效果、取消后坐力时需要决定的退出策略。

这里的立即回收可能产生明显跳变。产品需要柔和取消时，可以改成短恢复段；原文没有规定这一点。

12连射和压枪：文章留下了哪些设计问题

12.1 连射不是“每枪都重置为零”这么简单

如果射速为每分钟 600 发，每枪间隔是 0.1 秒。假设一枪曲线持续 0.38 秒，后几枪到来时，前枪尚未结束。需要决定旧贡献怎样保留、新贡献怎样加入。

若镜头当前仍保留上一枪 +1.3° 的贡献，而新枪仅把 previousPitch 重置到 0，那么旧贡献没有被回收或继承到可追踪状态。后续恢复可能只回收新枪，造成漂移。相反，若每次 Enter 都立即清掉旧贡献，连射又可能出现明显向下跳动。

12.2 两种常见补充方案

方案更新思路需要处理的地方
每枪独立曲线叠加每枪创建独立生命周期。把所有未结束曲线的当前偏移加起来，再对总偏移做差。多枪重叠、单枪退出归零、整体上限、同时回落造成的抵消。
维护连射累计偏移新枪在当前累计偏移上追加上抬；持续射击时按规则处理恢复；停火后统一回收累计偏移。重复入场要继承旧状态；恢复目标、连射弹数分段、玩家输入补偿。
# 补充：每枪独立曲线叠加的核心关系
currentTotal = Sum(shot.SampleOffset(now - shot.fireTime)
                   for shot in activeShots)
delta = currentTotal - previousTotal
ApplyCameraDelta(delta)
previousTotal = currentTotal

原文的 Persist 参数说明作者考虑了连射回正，但不足以判定最终采用哪种方案、是否混合两种思路。FPS 手感中的“逐枪弹序”“持续累计”“停火回正”也可以拆成不同层。

12.3 玩家压枪时，应该恢复到哪里

用一维 Pitch 举例，基础视角是 10°，后坐力加 +2°，玩家拖鼠标压下 −1°，当前视角变成 11°。之后完整回收系统的 +2°，结果是 9°，即保留玩家的 −1°输入。

这在“自动撤销全部后坐力贡献”的设计下是自洽的，但也可能带来：玩家已经压枪到目标，停火后镜头继续往下拉。另一种设计可以追踪玩家已经抵消的份额，只恢复未补偿部分；或在玩家明显移动视角后停止某种回正。具体选择取决于产品目标。

“移除后坐力贡献”和“返回开枪前朝向”不是同一个目标。前者保留玩家输入；后者可能需要覆盖、补偿或更新玩家输入。文章没有给出足够代码，不能把回正目标或鼠标处理方式当作已知事实。

12.4 像素阈值为什么要谨慎解释

IGNORE_RECOIL_RECOVER_PIX 用的是像素阈值；像素位移与实际转角的关系又受鼠标灵敏度、输入实现、ADS 倍率等影响。不能直接把“若干像素”当作“若干度”。应确认阈值检测在原始输入还是处理后的输入上。

12.5 相机限幅可能破坏差分回收

若相机已经接近最大 Pitch，系统请求再抬 +2°，但相机只允许抬 +0.5°，后坐力历史却仍记为 +2°。之后回收 −2°，就可能下降过量。需要让“已施加贡献”与实际限幅一致，或采用基础视角与效果偏移分离的合成方案。这是补充的工程边界，不是原文已经解决的问题。

13文章其余伪代码，也放到同一套思路里理解

13.1 FOV：当前值接口，不要当增量相加

原文 FOV 部分没有独立函数代码，只说明主相机和附属相机各自做曲线过渡，且每次使用实际 FOV 值。若当前目标是 70°，应设为 70°，不能向旧 FOV 再加 70°。

文章要求开镜途中关镜、关镜途中开镜时同步进度。意思是切换后不能突然从完整起点重放，否则 FOV 会跳。具体如何换算进度未展示；当开关镜曲线不同时，通常不能简单采用 1−u。

# 补充：一种保持数值连续的通用方法
def BeginFovTransition(newTarget, newDuration):
    startFov = currentFov      # 从屏幕当前值开始
    targetFov = newTarget
    elapsed = 0
    duration = newDuration

def TickFov(dt):
    elapsed += dt
    u = 1 if duration == 0 else Clamp01(elapsed / duration)
    currentFov = Lerp(startFov, targetFov, u, easing)
    camera.SetFov(currentFov)

这种重新取起点的方法保证数值连续，但不一定保持原曲线速度、总耗时或原作者希望的开镜进度。若要求精确承接原曲线，可从当前 FOV 反求新曲线进度，再接着推进；需要曲线单调且有可求逆的定义。

13.2 呼吸晃动：返回值本身更像曲线位置

原文代码

# JitterSimulator Tick
def Tick(self, dtime):
    x = -math.cos(self.jitter_time) * self.period
    y = -math.sin(2 * self.jitter_time) * self.amplitude
    self.jitter_time += (dtime * self.speed)
    return (x, y)

jitter_time 在三角函数中其实承担“相位”的作用；dtime×speed 推进相位。x 用 cos，y 用二倍相位的 sin，因此 y 在 x 一个完整周期内摆动两次，组合轨迹可以形成类似“8”字的闭合路径。哪个分量映射 Yaw、哪个映射 Pitch，片段没有说明。

虽然字段名叫 period，但在这段公式里它乘在 cos 外侧，是 x 的幅度系数，不是时间周期。实际频率由 speed 决定：若相位速度为 ω，x 的周期是 2π/ω，y 的周期是 π/ω。变量名和参数注释不能覆盖公式的数学意义。

原文文字说呼吸晃动“每帧需要处理变化量”，但这个函数本身没有相减，只返回当前 x/y。所以差分大概率在调用层完成，或使用另外的偏移合成层；这部分代码未展示。

# 补充：若调用的是增量相机接口
current = jitter.Tick(fixedDt)
delta = current - previousJitter  # 示意：向量减法
camera.Rotate(delta)
previousJitter = current

还要处理首帧：相位为 0 时 x=−period，y=0，并不从零偏移开始。可以先记录首样本作为基准，或让效果淡入；若关闭时要移除现有偏移，也要明确退出处理。

13.3 骨骼跟随：对局部旋转做差，再叠加到相机

原文代码

def BoneFollow(self):
    diffBonePitch, diffBoneYaw, diffBoneRoll = 0, 0, 0
    if self.BoneFollowEnable:
        if (self.lastBonePitch == 0 and self.lastBoneYaw == 0
                and self.lastBoneRoll == 0):
            curBoneTrans = self.target.GetBoneLocalTransform(self.BoneFollowName)
            self.lastBonePitch = curBoneTrans.pitch
            self.lastBoneYaw = curBoneTrans.yaw
            self.lastBoneRoll = curBoneTrans.roll
        else:
            curBoneTrans = self.target.GetBoneLocalTransform(self.BoneFollowName)
            curBonePitch = curBoneTrans.pitch
            curBoneYaw = curBoneTrans.yaw
            curBoneRoll = curBoneTrans.roll

            diffBonePitch = curBonePitch - self.lastBonePitch
            diffBoneYaw = curBoneYaw - self.lastBoneYaw
            diffBoneRoll = curBoneRoll - self.lastBoneRoll

            self.lastBonePitch = curBonePitch
            self.lastBoneYaw = curBoneYaw
            self.lastBoneRoll = curBoneRoll

    return diffBonePitch, diffBoneYaw, diffBoneRoll

流程是：默认输出零；未启用时直接保持零；首次采样只记录基准；后续读取当前骨骼角度，减去上次记录，再更新历史。这样相机跟随动画变化，而不会每步重复叠加完整骨骼姿态。

HP_Camera 是原文提到的动画相机效果骨骼。为什么取局部变换？因为要提取动画相对其坐标基准的旋转，避免把角色世界转身重复加到相机。GetBoneLocalTransform 的“局部”具体相对父骨骼、根骨骼还是骨架组件，仍要核对该引擎 API。原文把它解释为相对根骨骼的变化，但函数名本身不足以证明这点。

原文这段有三个实用边界

  • 用全零当首次采样标记不稳妥。骨骼合法姿态本来就可能全零，下一步又被误认为首帧，漏掉变化。应使用独立的 hasPreviousBoneSample 标志。
  • 欧拉角跨 ±180° 时不能直接减。从 179° 到 −179°，真实短路径是 +2°，直接相减却是 −358°。小角度场景可用最短角差；复杂三维旋转宜用四元数相对旋转，并明确乘法顺序和坐标空间。
  • 关闭再开启时要重建采样基准。否则停用期间变化可能在下一次启用时一次性加给相机。
# 补充：以度为单位的最短角差示例
def ShortestAngleDelta(current, previous):
    return (current - previous + 180.0) % 360.0 - 180.0

# 弧度版本对应把 180 / 360 换成 PI / (2*PI)。
# 三轴独立最短角差仍是小角度欧拉近似，不等于任意三维旋转合成。

14真正实现时，优先确认这八件事

  1. 明确相机接口。它接收当前值还是增量？角度用度还是弧度？Pitch/Yaw 参数顺序、正方向是什么？
  2. 分开目标与历史。保存上一采样的后坐力偏移，别拿整个相机朝向代替它。
  3. 完成所有阶段端点。不仅上抬要到峰值，下降也要到零，退出时不能留下未回收偏移。
  4. 显式推进阶段。修正时间后要切换状态；跨段剩余时间、零时长、短于单步的曲线都要处理。
  5. 每枪只选一次所需数据。ADS 数据、弹序与随机值何时确定要清楚，避免同一枪过程中意外变更目标。
  6. 给连射选择清晰的策略。旧贡献继续存在、新枪继承或叠加、停火回正目标，都不能只靠重启 Enter 隐式决定。
  7. 统一合成各镜头效果。尤其是 Roll 和 FOV 当前值的所有权，避免模块之间互相覆盖。
  8. 检查真实表现与边界。低帧率、短时长、快速连射、压枪、Pitch 限幅、切枪、开关效果时，曲线逻辑正确还不够，画面也要符合预期。

判断你是否读懂原文，可以用这句话：先用时间曲线决定“这一枪此刻应该贡献多少偏移”，再按相机接口把它转换为差分或当前值，最后与玩家输入及其他镜头效果合成。
