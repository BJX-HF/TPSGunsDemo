## 5. 待确认项

### 1) `AccumulatedPitch` 到底是什么量（**这条会决定整个系统的手感性格**）

计划 §P2 断言 1 说"连发 10 发后 `AccumulatedPitch` == 逐步累加和"，断言 3 说"停火后稳态偏移 == MaxKick × `RecoilReturnRatio`"。
两条同时成立，只有一种解释：**`AccumulatedPitch` 既是累加量、也是会回正的那个量**。

我的实现（也是这条推理的落地）：

```
每发：  AccumulatedPitch += 单发垂直Kick        （然后 Clamp 到 ±MaxVerticalKick）
停火：  峰值 = 进入回正那一刻的 AccumulatedPitch
回正：  AccumulatedPitch = Lerp(峰值, 峰值 × RecoilReturnRatio, RecoveryCurve(归一化时间))
```

因此 `RecoilReturnRatio = 0` → 回正到 0（竞技向：相机完全回正，但**弹道不回正**，玩家得自己压枪）；
`= 1` → 相机一点都不回正。**请确认这个解释与你的设计意图一致。**

### 2) 弹道链与相机链是刻意不共用同一个累计量的

- **相机链**：累加 + 回正（上面那套）。
- **弹道链**（P3）：`GetShotDirectionOffset(ShotIndex)` 是**纯函数**，只按当前发序号查 Pattern，**不做回正**。

这两者会把"相机看到的偏移"和"子弹实际落点"分开 —— 这正是计划 §3.3 决策 3 想要的
（`0 = 相机回正、弹道不回正，玩家需自己压枪`）。代价是：**如果 `RecoilReturnRatio` 设成 0，
准星位置就不再等于子弹落点**。这是"竞技向"的必然结果，但需要你确认接受。

### 3) 姿态倍率是瞬时切换，不做插值

Lyra 原有的 spread 姿态倍率是 `FInterpTo` 平滑的（`LyraRangedWeaponInstance.cpp` L180/L186/L192）。
后坐力侧我**刻意用瞬时判定**，原因是计划 §P4 要求
"各姿态结果比值 == 配置倍率比值（1e-3 容差）" —— 带插值的话在过渡期比值会被拉偏，断言不可靠。

代价：蹲下/起跳瞬间，下一发的手感会立刻变化（不会平滑过渡）。
**如果你要平滑，需要给资产再加一个 `PoseTransitionRate` 参数**，那会改动 P1 冻结的参数表。请拍板。
