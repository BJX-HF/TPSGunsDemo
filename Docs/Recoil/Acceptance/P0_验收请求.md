## 5. 待确认项

### 1) 编译命令必须追加 `-NoUBA`（环境问题，非代码问题）— **需你拍板是否写入计划文档**

本机直接跑计划 §P0 里给出的原始命令会**失败**：

```
Result: Failed (OtherCompilationError)
UbaSessionServer - SetFileInformationByHandle (FileDispositionInfo) failed on
  C:\ProgramData\Epic\UnrealBuildAccelerator\memgroups (Access is denied.)
```

原因：系统拦截了进程的**文件删除类**系统调用（`SetFileInformationByHandle(FileDispositionInfo)`），UBA（Unreal Build Accelerator）清理临时文件时被拒，导致整轮构建判定失败。加 `-NoUBA` 后走传统本地编译 executor，**构建成功**，仅末尾残留两条无害的 UBA 警告。

**建议**：把计划文档 §P0/§硬性规则 8 里的标准编译命令改为带 `-NoUBA` 的版本。
**本轮执行**：已按带 `-NoUBA` 的命令执行，未经你同意不回写计划文档。

### 2) `FRecoilShotResult` 比计划多了一个字段 `PoseMultiplier`

计划 §3.2 只写了类型名，未列字段。我按 P2 单测、P3 注入、P5 CSV 三处共用的需要，定义了 8 个字段：
`ShotIndex`、`VerticalKick`、`HorizontalKick`、`AccumulatedPitch`、`AccumulatedYaw`、`TimeSinceFire`、`PoseState`、`PoseMultiplier`。

前 6 个严格对应计划 §P5 的 CSV 列（顺序一致，导出时零映射代码）。后 2 个是为 P4 姿态验收表服务的诊断字段。
**请确认是否接受这 2 个额外字段**（若不要，P4 的验收数值表需要另想办法取数）。

### 3) 瞄准（Aiming）不进 `EPoseState` 枚举

计划 §P1 的倍率清单里有 4 个：`_Aiming / _Standing / _Crouching / _JumpingOrFalling`。
但"瞄准"与站/蹲/空中是**正交**关系（可以走路时瞄准、蹲着瞄准）。若把 Aiming 做进 `EPoseState`，会出现 8 种组合状态。

**我的处理**：`EPoseState` 只含 3 个姿态（+ `Count`）；Aiming 用 `[0,1]` 混合权重单独作用，最终
`总倍率 = GetPoseMultiplier(Pose) × Lerp(1, PoseMultiplier_Aiming, AimingAlpha)`。
**请确认这个合并语义符合你的预期。**

### 4) P1 的 `.uasset` 交付物用 Commandlet 生成

工程未启用 PythonScriptPlugin，无法用编辑器 Python 脚本建资产。我改为在 `LyraEditor` 模块加一个资产生成 Commandlet（`-run=LyraRecoilAssetGen`），可重复、可脚本化、幂等。
**请确认接受这种方式**（备选方案是你手动在编辑器里右键新建三份资产，我给出参数表照填）。
