### 关于"复用已有判定"这条要求

计划 §P4 要求"复用 Lyra 已有的 Crouch / Speed / Jump 判定（不重复造轮子）"。
落地方式：

- **判定来源复用**：`ComputeRecoilPoseState()` 读的就是 `UCharacterMovementComponent::IsCrouching()` / `IsFalling()`，与 `UpdateMultipliers()` 里 spread 用的是同一对调用。
- **瞄准权重复用**：P2 阶段已经把原本内联在 `UpdateMultipliers()` 里的瞄准权重计算提取成 `ULyraRangedWeaponInstance::ComputeAimingAlpha()`，spread 与后坐力共用同一份实现，不会随时间漂移。
- **刻意不复用的部分**：Lyra 原有的姿态倍率是 `FInterpTo` 平滑的（`LyraRangedWeaponInstance.cpp` L180/L186/L192）。后坐力侧**不做插值**，原因见 §5 待确认项 2。

### 恢复曲线：实现部分在 P2 已完成，P4 补的是"证明它真的生效"

`RecoveryCurve` 在 P2 就已经接进 `ApplyRecoveryStep()`：

## 5. 待确认项

### 1) 「Speed 判定」没有对应的资产参数（**需要你决定 P4 范围**）

计划 §P4 正文写的是"复用 Lyra 已有的 Crouch / **Speed** / Jump 判定"，
但 §P1 冻结的参数表里只有 `PoseMultiplier_Aiming / _Standing / _Crouching / _JumpingOrFalling` 四个，
**没有** `_Moving` / `_StandingStill` 这类移动相关的后坐力倍率。

我按"三个姿态 + 瞄准组合"实现（移动中归入 Standing）。
**如果你要移动中降低后坐力（或提高），需要新增 `PoseMultiplier_Moving` + 一个速度阈值参数** —— 那是改动 P1 的冻结契约，我没有擅自加。

### 2) 姿态倍率是瞬时切换，不做插值

Lyra 原有 spread 的姿态倍率用 `FInterpTo` 平滑。后坐力侧我**刻意不插值**，理由只有一个：
计划 §P4 要求"各姿态结果比值 == 配置倍率比值（1e-3 容差）"，带插值的话在
蹲下/起跳的过渡窗口内比值会被拉偏，断言不可靠。

代价：蹲下/起跳的瞬间，**下一发**的手感会立刻变化，而不是平滑过渡。
**如果你要平滑，需要给资产再加 `PoseTransitionRate` 参数**（同样是改 P1 冻结契约）。
我的建议是保持瞬时 —— 后坐力本来就是一个逐发的离散事件，单发级别的突变反而更好读。

### 3) 空中优先级高于蹲伏

"蹲着跳"（例如从掩体后蹲着起跳）用的是**空中**倍率 1.5，而不是蹲伏的 0.8。
理由是：脚已经离地，不该再享受蹲伏的稳定性加成。已固化成断言 `Lyra.Recoil.Pose.ResolvePriority`。
**如果游戏设计上希望蹲伏加成在空中也生效，说一声，改一行的事。**

### 4) 手动验收的"录像对比"仍需人工

`04_PoseMatrix.md` 的数值表是自动测出来的，但计划 §P4 要求的
"四种姿态各录一段相同操作，横向对比反弹幅度" 必须人在 PIE 里做。
表里已经预留了位置（§4），你确认后我把你的观测值一并归档。
