# 主 agent 预审问题（实现进行中）

以下来自实际源码检查，待子任务完成后交还修复并用构建/测试验收。此列表不是最终验收通过记录。

## A：转换

1. `BuildStrengthAdjustmentCandidate` 当前只重新归一化前 L 发。提高 V 时必须同时保留数组内 L…N−1 发的原逐发垂直角度，尾部 X 保留；需增加 L<N、L=0 的容纳强度测试。数组外和多个固定种子的随机尾差异必须供高级命令展示。
2. 全部 RichCurve 的有限性应包括切线权重及默认值；禁用的 WeaponVisual 字段仍需有限数保护。

## B：会话与提交

1. 数组长度相同不足以证明外部结构未改；检查对象属性事件能否区分元素数值编辑、整数组替换和重排，后两种必须重建 ID/清选择。
2. 统一提交需要正确的 PreEditChange 和 PostEdit 通知，元素编辑用属性链；一次操作最小字段变化，避免重复 ValidateProfile 导致重复错误。
3. 所有结构操作的前后顺序、L/N、曲线采样及角度差异需要显式预览，不能仅执行后刷新。

## C：预览

1. 当前原子步仅在发射时间和帧末拆分；带时间戳输入/姿态变化也必须作为事件边界。加入不落在帧末或发射时刻的输入测试，用独立直接 Runtime 调用比对。
2. 当前没有预览输入和输出的统一有限性阻断；源 NaN/Inf、曲线异常、RPM/步长/脚本等异常必须拒绝，不能只有 Warnings 后继续生成 Slate 数据。
3. `SetConfig` 把 SingleShot override 写在同一快照后切回 FromProfile，可能留下旧覆盖模式；模式回退要恢复原快照值或重建。
4. 列表中的发序号需区分发前弹道索引和 ApplyShot 后实际本发索引（新轮次重置由 Runtime 完成）。理论累计 Kick 应取实际本发索引和新种子，避免拿前一轮旧 ShotIndex 计算；弹道链继续保持真实调用顺序。
5. 配置相等/缓存 hash 必须比较完整输入脚本内容、FireInputs 内容与所有可影响结果的字段；长度相同不是等价。停止时刻不能超过用户尾时长。
