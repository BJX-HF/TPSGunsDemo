1 · 30 秒速查

控制台（PIE 里按 ~ 打开）一共 6 个开关 + 2 个命令，全部长这样：

命令默认作用
Lyra.Recoil.Enable 0/11 总开关。置 0 后弹道偏移恒为 0、相机一点不动。用来确认"你看到的抖动确实来自后坐力系统"。
Lyra.Recoil.Scale <f>1.0 全局调试倍率，乘在资产数值之上，不改资产。调手感时先用它快速找比例，满意了再写进资产。三轴（Pitch/Yaw/Roll）都乘。
Lyra.Recoil.Debug 0/10 屏幕左上角数值面板：每发的 Kick、累计偏移、状态机、姿态倍率。
Lyra.Recoil.DebugDraw 0/10 世界内可视化：绿线瞄准轴 / 红线相机偏移 / 黄点弹道 Pattern / 青条回正进度 / 品红弧 = Roll 倾角。
Lyra.Recoil.RollShake <f>1.0 Roll 实时振幅倍率。0 = 临时关掉 Roll（做 A/B 对比）；2 = 放大两倍便于观察。纯显示层，不改资产、不污染 CSV。
Lyra.Recoil.RollDebug 0/10 Roll 实时面板：实时值 + 生效参数 + ASCII 波形。独立于 Debug，可以同开。
Lyra.Recoil.Dump— 把本轮连发逐发导出成 CSV：Saved/RecoilDump_<时间戳>.csv（表头含 RollShake 列）。
Lyra.Recoil.ReloadProfile— 从磁盘强制重载后坐力资产。在编辑器里改资产不需要它，只用于"资产被编辑器之外的东西改了"。
最短验证路径 重启编辑器 → 落在 L_ShooterPerf → PIE → Lyra.Recoil.DebugDraw 1 → 长按左键打满 12 发 → 看黄点画出来的是不是「S」。
切到快捷栏第 2 格再打一轮 → 黄点应该变成「7」。
Roll 震屏的验证路径见 第 9 节。

3 · Debug 开关与效果详解

3.1 屏幕数值面板 Lyra.Recoil.Debug

面板固定刷在屏幕左上角，一共 6 行（第 4 行是 2026-09-17 新增的单发模型行）：

[Recoil] ON   Scale=x1.00   Profile=DA_Recoil_Rifle_S
  ShotIndex=5   Kick V=0.193 H=0.036
  Accum Pitch=0.835 Yaw=0.655   Cam Pitch=0.812 Yaw=0.639
  Mode=Interpolated   Stage=Lift   SubSteps=1   StageT=0.0217
  State=Accumulating   RecoveryTimer t=0.000 / delay=0.120 / prog=0.000
  Pose=Standing x1.000   Seed=20260917   History=6
位置字段含义
第 1 行ON / OFF 总开关状态。整块面板的颜色也跟着变：ON = 黄色，OFF = 银灰（扫一眼就知道当前有没有生效）
Scale=x1.00当前全局调试倍率（Lyra.Recoil.Scale）
Profile=当前武器用的后坐力资产名。切枪后这里会变，是"武器接线对不对"最快的判断依据
第 2 行ShotIndex本轮连发打到第几发（0 起）。打满 12 发后进入随机游走区
Kick V/H最近一发的垂直/水平增量（度，已含姿态倍率与全局 Scale）
第 3 行Accum Pitch/Yaw 逻辑偏移（度）。峰值 / 回正 / CSV / Golden / 测试读的都是它
Cam Pitch/Yaw 相机实际偏了多少（补间输出）。InstantWrite 下与左边完全相等； Interpolated 下会有斜坡，左右两个值对不上是正常的（见第 10.4 节）
第 4 行
（单发模型）		Mode 这把枪用哪套单发模型：InstantWrite / Interpolated。 切枪对比两把枪的模型差异，就看这里（见第 10 节）
Stage 当前处于哪一段：-（无 · 瞬时模式下恒为 -）/ Lift / Rebound / Settle / Drop
SubSteps 本帧实际推进了几个固定子步（每步 = 1/60 秒）。 常态是 1（60fps）或 2~3（高刷）；跳到 8 说明本帧卡了，时间被丢弃
StageT当前段的内部进度（秒）。和该段的时长对比，就能知道走到哪了
第 5 行State 状态机：Idle → Accumulating → 停火超过 delay → Recovering → Idle
t距上次开火过了多少秒（用来对照 delay）
delay / prog该资产的 RecoveryDelay（插值模式下它也兼任 Settle 段时长）；prog = 回正进度 [0,1]
第 6 行Pose 姿态：Standing / Crouching / JumpingOrFalling
x1.000该发实际用的总倍率（姿态倍率 × 瞄准混合倍率）。蹲下应该看到 0.800，瞄准时 0.750，跳起来 1.500
Seed / History本轮随机种子；History = 已记录的发数（Dump 导出的就是这些行）
顺手能做的两个验证 ① 蹲下开火 → 第 5 行 x 应该变 0.800；
② 右键瞄准时开火 → 应该变 0.750，同一发的 Kick 明显更小。
倍率是瞬时切换、不做插值，这是刻意设计（见 PROGRESS §6 第 10 条）。

3.2 世界内可视化 Lyra.Recoil.DebugDraw

从角色眼睛位置往前画一根 1500cm 的线，配合四个图元：

图元颜色是什么
细线绿色 真实瞄准轴（ControlRotation）。永远不受后坐力影响 —— 它不动，就是"相机偏移只改显示层、没碰玩家输入"的可视证据。
粗线 + 点红色 相机链当前朝向 = 瞄准轴 + 累计 Pitch/Yaw。这就是玩家屏幕上真正看到的方向； 它和绿线的夹角就是当前后坐力偏移量。
一排点黄色 Pattern 点阵：把前 PatternLength 发（现在是 12 发）的弹道方向一次性画出来。 不用真开火就能看出"这把枪的形状是什么样"。
竖条青色（底衬银灰） 回正进度：底端 0，满刻度 100cm 对应进度 1.0。银灰是底条，青色是填充。
文字青色 Recoil <State> Shot=<n> Pitch=.. Yaw=.. Prog=.. Pose=..，跟面板是同一份数据。
两个已知的"不是 bug" ① 绿线用的是 ControlRotation，不是 GA 里的 CameraTowardsFocus，所以是近似瞄准轴（PROGRESS §6 第 18 条）。
② DrawDebug 只在非 Shipping 构建里存在（ENABLE_DRAW_DEBUG），打包版没有。

3.3 怎么"看"后坐力而不靠感觉

  1. Lyra.Recoil.DebugDraw 1 看形状（黄点）。
  2. Lyra.Recoil.Dump + plot-recoil-csv.py 看数值曲线（可多份叠加对比）。
  3. Lyra.Recoil.Scale 0.3 把后坐力整体缩到 30%，慢下来看细节（回正是否顺、有没有过冲）；这是最容易发现"回正看着别扭"的方法。

4 · 怎么改一把枪的后坐力

4.1 资产在哪

枪后坐力资产形状
槽位 0（出生默认）Content/Weapons/Recoil/DA_Recoil_Rifle_SS 型 · 小
槽位 1Content/Weapons/Recoil/DA_Recoil_Rifle_77 字型 · 稍大

双击打开就是普通 Data Asset 面板，改完 PIE 里立刻生效，不需要重载、不需要重启。

4.2 参数逐个解释

参数作用调大的后果
RecoilPerShot_Vertical 单发垂直基准（度）。整体强度的总闸 整枪更"跳"，抬枪更快到上限
RecoilPerShot_Horizontal 单发水平基准（度） 左右摆幅变大，形状更"胖"。它的水平/垂直比值决定形状看起来像不像样品
PatternPoints 形状。索引 = 第几发；X ∈ [-1,1] 右为正（每发水平增量），Y ∈ [0,1] 上为正（每发垂直倍率） 改数组 = 改形状。想镜像就把所有 X 取反
PatternLength 固定 Pattern 覆盖几发，之后的发数进入确定性随机游走 固定段更长，"记住弹道"更有价值
HorizontalRandomRange 固定 Pattern 之后水平随机游走的幅度上限 尾部更散、更难压
VerticalKickCurve 趋势：射击序号 → 垂直倍率。曲线的上升 = "越打越跳" 后段抬得更凶。注意它只作用于垂直，保证水平形状严格可比对
RecoveryCurve 回正进度曲线。X = 归一化回正时间，Y = 回正进度。线性 = 匀速回正 上凸 = 快回后慢；下凸 = 慢回后快
RecoveryDelay 停火后多久开始回正（秒） 更容易"续枪"，连发手感更连贯
RecoveryTime 回正总时长（秒） 回正更慢、更粘
RecoilReturnRatio 核心手感开关。[0,1]。0 = 相机完全回正（玩家得自己压枪，竞技向）；1 = 完全不回正 越大，停火后残留偏移越多
MaxVerticalKick / MaxHorizontalKick 累加偏移的钳制上限（度） 长连发的最终偏移更大。7 字型要"画完横杠"就必须给足水平上限
PoseMultiplier_Aiming / Standing / Crouching / JumpingOrFalling 姿态倍率，全部 ∈ (0,5]。与姿态相乘不是相加 蹲下 0.8、站 1.0、空中 1.5、瞄准 0.75 是项目基线
RandomSeedMode / FixedRandomSeed 随机种子模式。测试与 Golden 必须用 Fixed Random 模式手感更"活"，但序列不可复现
── 以下 6 项在 Recoil | SingleShot 分组，属于"单发模型"，详见第 10 节 ──
SingleShotMode 单发模型总开关。InstantWrite（瞬时写入，默认）/ Interpolated（插值，带四段顿挫） 切到 Interpolated 才有下面 5 项；改完要重导 Golden
LiftDuration 上升斜坡耗时（秒）。默认 0.045 抬得更慢更拖；为 0 等于退化回瞬时
ReboundDuration 回弹段时长（秒）。默认 0.030 「一顿」更明显但更钝
ReboundRatio 「一顿」的深度，回弹到峰值的比例。默认 0.72，∈[0,1] 越接近 1 越像老模型（几乎不回弹）；越小顿挫越深
LiftCurve Lift 段形状曲线，横轴 = 段内归一化时间。默认 Ease-Out（快起慢收） 改成线性会显得机械
ReboundCurve Rebound 段形状曲线。默认线性 回弹段只有 30ms，一般不用动
最重要的一条职责划分（别再混淆） PatternPoints 只描述形状，两个分量恒定落在归一化区间内；
"越打越高"这种趋势由 VerticalKickCurve 承担。
实际角度 = RecoilPerShot_Vertical × Pattern.Y × VerticalKickCurve(i)。
把上升趋势写进 Pattern.Y 会被资产校验直接拦下（Y 不允许 > 1）。

4.3 常见调整目标 → 怎么动

想要的效果动哪个
整体更稳（更小）降 RecoilPerShot_Vertical + 降 RecoilPerShot_Horizontal
整体更飘（更大）升上面两个；同时确认 Max*Kick 别卡住累计
换形状（S ↔ 7 ↔ 直线）只改 PatternPoints 的 X 序列。形状"想多胖"由 RecoilPerShot_Horizontal 缩放
形状镜像（横杠换边）把 PatternPoints 里所有 X 取反
前几发稳、后段炸陡化 VerticalKickCurve 的后半段
回正更快 / 更粘改 RecoveryDelay + RecoveryTime
更依赖压枪（竞技向）RecoilReturnRatio → 0
蹲下更稳 / 跳着更飘PoseMultiplier_Crouching / PoseMultiplier_JumpingOrFalling
只想临时试个量级，不想动资产Lyra.Recoil.Scale 0.5，满意了再写进资产
── 单发模型相关（第 10 节） ──
单发想要「抬起来 → 回弹一下 → 稳住」的顿挫 SingleShotMode = Interpolated → 再调 ReboundRatio（越小越深）+ ReboundDuration
斜坡抬得太慢 / 太急LiftDuration（0.02 ~ 0.06 区间试手感）+ LiftCurve
某把枪想改回老的瞬时手感SingleShotMode = InstantWrite（默认值，改完重导 Golden）

4.4 改完要做什么

  1. 保存资产（Ctrl+S）。未保存的改动在 PIE 里也生效，但退出编辑器会丢。
  2. 不用敲 Lyra.Recoil.ReloadProfile —— PIE 和编辑器同进程共享同一个 UObject，改完下一帧就生效。
  3. 如果改的是 DA_Recoil_Rifle（Golden 基准那份），必须重导 Golden，否则 Lyra.Recoil.Pattern.Golden 会 FAIL 并提示 stale： 
    powershell -ExecutionPolicy Bypass -File "D:\TPSGunsDemo\TPSGunsDemo\Docs\Recoil\Tools\gen-recoil-golden.ps1"
    改 DA_Recoil_Rifle_S / _7 不需要（它们不进 Golden）。
  4. 如果改了姿态倍率或单发基准，Docs/Recoil/04_PoseMatrix.md 的实测表要重跑更新。
  5. 改完跑一遍自动化测试（编辑器开着就行）： 
    AutomationTestToolset.RunTestsByFilter("StartsWith:Lyra.Recoil")
    预期 19/19。

5 · 怎么新增一把枪

先分清两种需求，工作量差一个数量级：

需求做法要动几个资产
A. 只换后坐力（模型/动画/伤害/开火方式全沿用现有步枪） 复制「后坐力资产 + 武器链」三件套3 个（复制品）+ 1 个新后坐力资产
B. 真·新枪（不同模型/动画/伤害/弹匣） A 的基础上再换 B_Rifle 模型、AbilitySet、伤害 GE6~10 个

下面走 A，用"再加一把 7 字型但更飘的枪"当例子。全程在编辑器的内容浏览器里右键复制即可。

5.1 理清一条武器链的四层

ID_xxx         InventoryItemDefinition       快捷栏里"那件东西"（图标、显示名、指向装备定义）
  └─ WID_xxx   EquipmentDefinition            装备定义：生成哪个 Instance、挂哪些 Actor、授哪些能力

9 · Roll 震屏与实时调试（P8）

这一节是 2026-09-17 新增的（P8） 依据《FPS 相机镜头设计与实现（脱敏版）》§1/§2/§2.1/§2.2/§7。
完整策划案 + 实现方案见 Docs/Recoil/08_CameraRollShake.md。

9.1 一句话：Roll 和后坐力是两套东西

这是本节最重要的一条，先看清楚再往下看：

Pitch / Yaw 后坐力Roll 震屏
数学模型积分：每发累加增量解析：按当前时刻直接求解
是否累加是（AccumulatedPitch += Kick）否
停火后走回正曲线，停在稳态偏移衰减到零，围绕零点往复后归零
长连发表现弹道持续上抬，越打越偏每发重新起震，始终围绕零点
为什么不能把 Roll 塞进 Pitch/Yaw 试过，会坏：Roll 会像 Pitch 一样单向漂移、永远回不到零点，看起来是"镜头歪了"而不是"抖了一下"。 更严重的是它会污染回正逻辑 —— 回正曲线是给"弹道上抬"设计的，套在往复震动上毫无意义。
两者除了"都作用在相机 POV 上"以外，没有任何共享逻辑。

9.2 手感是什么样

  • 短：一次震动总时长 0.22 秒，比回正（0.3~0.4 秒）还短。它是"开火瞬间的爆点"。
  • 快：一个震动周期 0.055 秒 —— 一次震动里抖 4 个来回，所以显得脆。周期拉长会变成"慢慢歪一下"，像喝醉了。
  • 必回零：震动结束精确归零，不留任何残留。
  • 幅度小：起始 0.6°，连射最多涨到 1.5°。Roll 是"歪头"方向，人眼比上下偏移更敏感，同样的角度看起来歪得更厉害。
  • 前几发稳、后段起来：第 0~3 发用基准振幅；第 4 发起每发 +0.05°，封顶 +0.9°。单点射几乎感觉不到，扫射时明显。
  • 带一点随机：每发相位有 ±0.35 rad 的小扰动。不加的话连发时震动会完全同步叠加，看起来像机械振动，很假。

10.1 一句话：现在有两套，按枪选

10.5 低帧率怎么处理（Lyra.Recoil.* 相关的实现约束）

验收标准是「采样轨迹一样」—— 60fps 和 144fps 下同一发的曲线必须重合。做法三条：

手段具体值解决什么问题
固定子步长FixedSubStepSeconds = 1/60 不管你显示器多少帧，内部一律按 1/60 秒为最小步推进。 帧率只影响一帧推几个子步，不影响轨迹本身
子步上限MaxSubStepsPerAdvance = 8 防「死亡螺旋」：卡顿时本帧最多推 8 步，超出的时间丢弃并直接推整条轴到稳态。 宁可长帧吞掉一点时间，也不能让一帧里无限循环
尾段吸附见下方伪码 修掉 off-by-one：若不吸附，阶段终值可能永远不被采样到， 导致 60 / 144fps 的终点差一点点

尾段吸附的关键意思（策划版）：「如果这一小步跨过了段的终点，就直接落在终点上」。

// AdvanceInterpolatedSubStepBy() —— 尾段吸附
StageDuration = 这一段的时长
Advanced      = 已过时间 + 一个子步

if (Advanced < StageDuration && (StageDuration - Advanced) < 一个子步)
    已过时间 = StageDuration        // ← 离终点不足一步：直接吸附，保证终值被采样
else
    已过时间 = min(Advanced, StageDuration)
刻意没做的一件事：不冲刷「零头」 每帧算完子步循环后，累加器里通常会剩一个不足 1/60 秒的零头。 按直觉应该「顺便把它推完」，但不行 —— 零头的大小和帧率强相关， 冲刷就等于让帧率影响轨迹，直接违反「采样轨迹一样」。
实测：冲刷会让 60fps 与 144fps 产生约 0.006 的偏差；不冲刷则相机链偏差严格为 0。 代码里这段有显式注释标明「刻意不做」，别当成漏写。
Roll 震屏不走子步循环（刻意区分） Roll 是解析解（衰减包络 × 周期项），帧率只影响采样密度，怎么采都对；
Pitch/Yaw 是逐帧增量累加，帧率一变就漂移 —— 所以只有它需要固定子步。
Roll 的细节见本文第 9 节。

11 · 回正扣减压枪量（P10 · 2026-09-20）

11.1 一句话：回正不再把你压的枪还给你

以前：开枪把准星顶高 10°，你往下压 4° 把它拉回目标 —— 松手回正时偏移从 10° 回到底， 那 4° 被还回去了，准星比目标低了 4°，你得再抬一次。

现在：回正量扣掉你压的那部分。你压多少，就少回多少。压过头（压的比能回正的还多）， 回正量归零 —— 也就是只回正到最后一发子弹射出的位置。

两把枪都是这个规则，Pitch / Yaw 两轴同一条公式。

11.2 公式（想手算就照这个）

原本回正量 = 峰值 − 峰值 × RecoilReturnRatio
实际回正量 = clamp(原本回正量 − 压枪量, 0, 原本回正量)
回正终止值 = 峰值 − 实际回正量
你压了多少原本回正量实际回正量准星最终停在哪
03.753.75与改动前完全一样
1.0°3.752.75少回 1°：停在目标上
3.75°3.750回正量刚好归零
20°（压过头）3.750停在最后一发的位置，不再回

11.3 总开关：bCompensationAwareRecovery

每把枪的资产上，Recoil | Recovery 分类里。默认开启。

  • 关掉它 → 退回旧公式（终止值 = 峰值 × RecoilReturnRatio），用于 A/B 对照。
  • 没压枪时两条路径完全相同 —— 所以"我没压枪也觉得准星变飘了"不是这套逻辑引起的。
  • 压枪量本身在开关关闭时照常显示，只是不参与回正。

11.4 看数：面板多出来的那一行

Lyra.Recoil.Debug 1
  PushComp P=0.000 Y=0.000   FrozenComp P=0.000 Y=0.000   AimNow=(0.00, 0.00)
字段是什么
PushComp P / Y实时压枪量：相对本轮第一发，你把准星往后坐力反方向拉了多少度。往下压 / 往左拉为正
FrozenComp P / Y进入回正时冻结的快照 —— 回正目标真正用的是它
AimNow最近一次采样到的 ControlRotation，真值基准
两条容易被当成 bug 的行为（都是刻意的） ① 压枪量只在"开始回正"那一刻冻结。RecoveryDelay 之内继续压的枪算数； 回正开始之后再动鼠标不会改变落点。
② 连续多轮开火时，压枪量会一轮一轮垒进残留偏移，顶到 MaxVerticalKick / MaxHorizontalKick 后停住（不再增长）。 观感上不可见（准星就是显示层），但你的鼠标会一轮比一轮多压一点。 觉得不舒服就把 RecoilReturnRatio 调小，或关掉总开关。

11.5 yaw 也会被扣（这是你拍板的）

连发过程中主动拉枪追目标，回正会把视角拽回开火前的位置 —— 因为系统分不出"你在压后坐力"和"你在追人"，两者都是同一笔鼠标位移。 只想要"垂直扣压枪、水平随便拉"，就把 bCompensationAwareRecovery 关掉。
