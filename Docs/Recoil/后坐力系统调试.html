1 · 30 秒速查

控制台（PIE 里按 ~ 打开）里，后坐力一共 6 个开关 + 2 个命令，全部长这样：

命令默认作用
Lyra.Recoil.Enable 0/11 总开关。置 0 后弹道偏移恒为 0、相机一点不动。用来确认"你看到的抖动确实来自后坐力系统"。
Lyra.Recoil.Scale <f>1.0 全局调试倍率，乘在资产数值之上，不改资产。调手感时先用它快速找比例，满意了再写进资产。三轴（Pitch/Yaw/Roll）都乘。
Lyra.Recoil.Debug 0/10 屏幕左上角数值面板：每发的 Kick、累计偏移、状态机、姿态倍率。
Lyra.Recoil.DebugDraw 0/10 世界内可视化：绿线瞄准轴 / 红线相机偏移 / 黄点弹道 Pattern / 青条回正进度 / 品红弧 = Roll 倾角。
Lyra.Recoil.RollShake <f>1.0 Roll 实时振幅倍率。0 = 临时关掉 Roll（做 A/B 对比）；2 = 放大两倍便于观察。纯显示层，不改资产、不污染 CSV。
Lyra.Recoil.RollDebug 0/10 Roll 实时面板：实时值 + 生效参数 + ASCII 波形。独立于 Debug，可以同开。
Lyra.Recoil.Dump— 把本轮连发逐发导出成 CSV：Saved/RecoilDump_<时间戳>.csv（表头含 RollShake 列）。
Lyra.Recoil.ReloadProfile— 从磁盘强制重载后坐力资产。在编辑器里改资产不需要它，只用于"资产被编辑器之外的东西改了"。
最短验证路径 重启编辑器 → 落在 L_ShooterPerf → PIE → Lyra.Recoil.DebugDraw 1 → 长按左键打满 12 发 → 看黄点画出来的是不是「S」。
切到快捷栏第 2 格再打一轮 → 黄点应该变成「7」。
Roll 震屏的验证路径见 第 7 节。
散布的验证路径：Lyra.Recoil.SpreadDebug 1 → 连发 → 看 Cone: raw 是不是"每发涨 addPerShot、到 max 封顶"。 详见 第 9 节。

散布（Spread）是另一套东西。它的数值配置已经并入 DA_Recoil_* 的 Recoil | Spread 分类（和后坐力同一张表）， 但屏幕可视化仍然分两拨 —— 新面板跟着 Lyra.Recoil.*， 画弹道还是得用 Lyra 原生的（小写）lyra.Weapon.*：

命令默认作用
Lyra.Recoil.SpreadDebug 0/10 散布实时面板：走的是哪条链路 / 裸锥角 → 最终锥角 / 瞄准与移动倍率 / 当前姿态四参数 / 换算好的半角。独立于 Debug 与 RollDebug，可同开。 详见 §9.4。
lyra.Weapon.DrawBulletTraceDuration <秒>0 看真实弹道的主要手段：把每颗弹丸的弹道画成红线（一颗一条）， 并在发射点画一根 100cm 的黄色短参考线。散布 = 红线相对黄线的离散程度。 （另有"看准星张开幅度"的实时读法，见 §9.4。）
lyra.Weapon.DrawBulletHitDuration <秒>0 在弹着点画红点。
lyra.Weapon.DrawBulletHitRadius <cm>3 上面那个红点的半径。
散布最省事的一条路 Lyra.Recoil.SpreadDebug 1 → 面板第二行直接写着 Cone: raw=… -> effective=…。准星看起来多大、弹道散成什么样，跟这两个数对不上就是有问题。
要数值化验证"每发 +0.28°、第 7 发到顶"这类设计意图，看 CSV 第 8 列 （Lyra.Recoil.Dump），不用靠眼睛估。
颜色会撞，先知道再开 开了 lyra.Weapon.DrawBulletTraceDuration 之后，世界里会同时有两套红线、两种黄： 后坐力的红/黄来自 Lyra.Recoil.DebugDraw，Lyra 的红/黄来自上面这条命令。 怎么区分见 §3.2 末尾的对照；散布本身的调试手段全量清单在 第 9 节。

3 · Debug 开关与效果详解

3.1 屏幕数值面板 Lyra.Recoil.Debug

面板固定刷在屏幕左上角，一共 6 行（第 4 行是单发模型行）：

[Recoil] ON   Scale=x1.00   Profile=DA_Recoil_Rifle_S
  ShotIndex=5   Kick V=0.193 H=0.036
  Accum Pitch=0.835 Yaw=0.655   Cam Pitch=0.812 Yaw=0.639
  Mode=Interpolated   Stage=Lift   SubSteps=1   StageT=0.0217
  State=Accumulating   RecoveryTimer t=0.000 / delay=0.120 / prog=0.000
  Pose=Standing x1.000   Seed=20260917   History=6
位置字段含义
第 1 行ON / OFF 总开关状态。整块面板的颜色也跟着变：ON = 黄色，OFF = 银灰（扫一眼就知道当前有没有生效）
Scale=x1.00当前全局调试倍率（Lyra.Recoil.Scale）
Profile=当前武器用的后坐力资产名。切枪后这里会变，是"武器接线对不对"最快的判断依据
第 2 行ShotIndex本轮连发打到第几发（0 起）。打满 12 发后进入随机游走区
Kick V/H最近一发的垂直/水平增量（度，已含姿态倍率与全局 Scale）
第 3 行Accum Pitch/Yaw 逻辑偏移（度）。峰值 / 回正 / CSV 读的都是它
Cam Pitch/Yaw 相机实际偏了多少（补间输出）。InstantWrite 下与左边完全相等； Interpolated 下会有斜坡，左右两个值对不上是正常的（见第 8.4 节）
第 4 行
（单发模型）		Mode 这把枪用哪套单发模型：InstantWrite / Interpolated。 切枪对比两把枪的模型差异，就看这里（见第 8 节）
Stage 当前处于哪一段：-（无 · 瞬时模式下恒为 -）/ Lift / Rebound / Settle / Drop
SubSteps 本帧实际推进了几个固定子步（每步 = 1/60 秒）。 常态是 1（60fps）或 2~3（高刷）；跳到 8 说明本帧卡了，时间被丢弃
StageT当前段的内部进度（秒）。和该段的时长对比，就能知道走到哪了
第 5 行State 状态机：Idle → Accumulating → 停火超过 delay → Recovering → Idle
t距上次开火过了多少秒（用来对照 delay）
delay / prog该资产的 RecoveryDelay（插值模式下它也兼任 Settle 段时长）；prog = 回正进度 [0,1]
第 6 行Pose 姿态：Standing / Crouching / JumpingOrFalling
x1.000该发实际用的总倍率（姿态倍率 × 瞄准混合倍率）。蹲下应该看到 0.800，瞄准时 0.750，跳起来 1.500
Seed / History本轮随机种子；History = 已记录的发数（Dump 导出的就是这些行）
顺手能做的两个验证 ① 蹲下开火 → 第 5 行 x 应该变 0.800；
② 右键瞄准时开火 → 应该变 0.750，同一发的 Kick 明显更小。
倍率是瞬时切换、不做插值，这是刻意设计。

3.2 世界内可视化 Lyra.Recoil.DebugDraw

从角色眼睛位置往前画一根 1500cm 的线，配合四个图元：

图元颜色是什么
细线绿色 真实瞄准轴（ControlRotation）。永远不受后坐力影响 —— 它不动，就是"相机偏移只改显示层、没碰玩家输入"的可视证据。
粗线 + 点红色 相机链当前朝向 = 瞄准轴 + 累计 Pitch/Yaw。这就是玩家屏幕上真正看到的方向； 它和绿线的夹角就是当前后坐力偏移量。
一排点黄色 Pattern 点阵：把前 PatternLength 发（现在是 12 发）的弹道方向一次性画出来。 不用真开火就能看出"这把枪的形状是什么样"。
竖条青色（底衬银灰） 回正进度：底端 0，满刻度 100cm 对应进度 1.0。银灰是底条，青色是填充。
文字青色 Recoil <State> Shot=<n> Pitch=.. Yaw=.. Prog=.. Pose=..，跟面板是同一份数据。
两个已知的"不是 bug" ① 绿线用的是 ControlRotation，不是 GA 里的 CameraTowardsFocus，所以是近似瞄准轴。
② DrawDebug 只在非 Shipping 构建里存在（ENABLE_DRAW_DEBUG），打包版没有。
再开一条命令就撞色：Lyra 原有的弹道调试 只要敲了 lyra.Weapon.DrawBulletTraceDuration 2（散布调试的唯一手段，见 第 9 节）， 世界里就会出现第二套红线与黄色图元。两者的区分办法：
颜色后坐力（Lyra.Recoil.DebugDraw）Lyra 散布（lyra.Weapon.*）
红 一条：相机链当前朝向，起点 = 眼睛高度， 长度固定 1500cm，粗细 2.5 每颗弹丸一条：真实弹道，起点 = 相机焦点投影处的发射点， 长度 = MaxDamageRange（默认 25000cm），粗细 1.0
黄 一串点（Pin，半径 6）：PatternLength 发的弹道方向点阵 一段短线（100cm）：发射点沿瞄准方向的参考线，粗细 2.0
一句话记法：跟着枪口一起跳、且永远是同一条的是后坐力；一颗弹丸一条、乱飞的是散布。

3.3 怎么"看"后坐力而不靠感觉

  1. Lyra.Recoil.DebugDraw 1 看形状（黄点）。
  2. Lyra.Recoil.Dump + plot-recoil-csv.py 看数值曲线（可多份叠加对比）。
  3. Lyra.Recoil.Scale 0.3 把后坐力整体缩到 30%，慢下来看细节（回正是否顺、有没有过冲）；这是最容易发现"回正看着别扭"的方法。

4 · 怎么改一把枪的后坐力

4.1 资产在哪

枪后坐力资产形状
槽位 0（出生默认）Content/Weapons/Recoil/DA_Recoil_Rifle_SS 型 · 小
槽位 1Content/Weapons/Recoil/DA_Recoil_Rifle_77 字型 · 稍大

双击打开就是普通 Data Asset 面板，改完 PIE 里立刻生效，不需要重载、不需要重启。

4.2 参数逐个解释

参数作用调大的后果
RecoilPerShot_Vertical 单发垂直基准（度）。整体强度的总闸 整枪更"跳"，抬枪更快到上限
RecoilPerShot_Horizontal 单发水平基准（度） 左右摆幅变大，形状更"胖"。它的水平/垂直比值决定形状看起来像不像样品
PatternPoints 形状。索引 = 第几发；X ∈ [-1,1] 右为正（每发水平增量），Y ∈ [0,1] 上为正（每发垂直倍率） 改数组 = 改形状。想镜像就把所有 X 取反
PatternLength 固定 Pattern 覆盖几发，之后的发数进入确定性随机游走 固定段更长，"记住弹道"更有价值
HorizontalRandomRange 固定 Pattern 之后水平随机游走的幅度上限 尾部更散、更难压
VerticalKickCurve 趋势：射击序号 → 垂直倍率。曲线的上升 = "越打越跳" 后段抬得更凶。注意它只作用于垂直，保证水平形状严格可比对
RecoveryCurve 回正进度曲线。X = 归一化回正时间，Y = 回正进度。线性 = 匀速回正 上凸 = 快回后慢；下凸 = 慢回后快
RecoveryDelay 停火后多久开始回正（秒） 更容易"续枪"，连发手感更连贯
RecoveryTime 回正总时长（秒） 回正更慢、更粘
RecoilReturnRatio 已于 2026-09-21 删除（见第 10 节）—— 回正终点由「本梭累计压枪量」直接决定，峰值不参与、不再有残留比例
MaxVerticalKick / MaxHorizontalKick 累加偏移的钳制上限（度） 长连发的最终偏移更大。7 字型要"画完横杠"就必须给足水平上限
PoseMultiplier_Aiming / Standing / Crouching / JumpingOrFalling 姿态倍率，全部 ∈ (0,5]。与姿态相乘不是相加 蹲下 0.8、站 1.0、空中 1.5、瞄准 0.75 是项目基线
RandomSeedMode / FixedRandomSeed 随机种子模式。要复现同一串弹道就必须用 Fixed Random 模式手感更"活"，但序列不可复现
── 以下 6 项在 Recoil | SingleShot 分组，属于"单发模型"，详见第 8 节 ──
SingleShotMode 单发模型总开关。InstantWrite（瞬时写入，默认）/ Interpolated（插值，带四段顿挫） 切到 Interpolated 才有下面 5 项
LiftDuration 上升斜坡耗时（秒）。默认 0.045 抬得更慢更拖；为 0 等于退化回瞬时
ReboundDuration 回弹段时长（秒）。默认 0.030 「一顿」更明显但更钝
ReboundRatio 「一顿」的深度，回弹到峰值的比例。默认 0.72，∈[0,1] 越接近 1 越像老模型（几乎不回弹）；越小顿挫越深
LiftCurve Lift 段形状曲线，横轴 = 段内归一化时间。默认 Ease-Out（快起慢收） 改成线性会显得机械
ReboundCurve Rebound 段形状曲线。默认线性 回弹段只有 30ms，一般不用动
最重要的一条职责划分（别再混淆） PatternPoints 只描述形状，两个分量恒定落在归一化区间内；
"越打越高"这种趋势由 VerticalKickCurve 承担。
实际角度 = RecoilPerShot_Vertical × Pattern.Y × VerticalKickCurve(i)。
把上升趋势写进 Pattern.Y 会被资产校验直接拦下（Y 不允许 > 1）。

4.3 常见调整目标 → 怎么动

想要的效果动哪个
整体更稳（更小）降 RecoilPerShot_Vertical + 降 RecoilPerShot_Horizontal
整体更飘（更大）升上面两个；同时确认 Max*Kick 别卡住累计

7 · Roll 震屏与实时调试

7.1 一句话：Roll 和后坐力是两套东西

这是本节最重要的一条，先看清楚再往下看：

Pitch / Yaw 后坐力Roll 震屏
数学模型积分：每发累加增量解析：按当前时刻直接求解
是否累加是（AccumulatedPitch += Kick）否

7.2 手感是什么样

  • 短：一次震动总时长 0.22 秒，比回正（0.3~0.4 秒）还短。它是"开火瞬间的爆点"。
  • 快：一个震动周期 0.055 秒 —— 一次震动里抖 4 个来回，所以显得脆。周期拉长会变成"慢慢歪一下"，像喝醉了。
  • 必回零：震动结束精确归零，不留任何残留。
  • 幅度小：起始 0.6°，连射最多涨到 1.5°。Roll 是"歪头"方向，人眼比上下偏移更敏感，同样的角度看起来歪得更厉害。
  • 前几发稳、后段起来：第 0~3 发用基准振幅；第 4 发起每发 +0.05°，封顶 +0.9°。单点射几乎感觉不到，扫射时明显。
  • 带一点随机：每发相位有 ±0.35 rad 的小扰动。不加的话连发时震动会完全同步叠加，看起来像机械振动，很假。

8.1 一句话：现在有两套，按枪选

9.2 新模型：姿态-角度直接模型（计算链）

把中间那层 heat 删掉，直接算角。每一把枪在每个姿态下各有一组参数：

① 开火加热（每扣一次扳机）        CurrentSpreadAngle += SpreadAddPerShot_<姿态>
                                 CurrentSpreadAngle  = clamp(它, Base, Max)

② 停火回落（每帧）               停火时长 <= SpreadRecoveryDelay   → 不动
                                否则 CurrentSpreadAngle -= SpreadRecoverRate_<姿态> × dt
                                 CurrentSpreadAngle  = clamp(它, Base, Max)

③ 结算最终锥角（发弹那一刻）      最终锥角 = CurrentSpreadAngle
                                          × SpreadAimingMultiplier（瞄准，[0,1] 混合权重）
                                          × SpreadMovementMultiplier（站定↔跑动，按速度 ramp）

④ 喂给圆锥采样                    半角(弧度) = 最终锥角 × 0.5 × π/180
                                 VRandConeNormalDistribution(AimDirWithRecoil, 半角, SpreadExponent)
三个必须记住的口径 ① 单位是"全锥角（直径角），度" —— 不是半角，也不是面积。 第 ④ 步的 × 0.5 是唯一的换算点（LyraGameplayAbility_RangedWeapon.cpp L419）。
② 基础角是"地板"，不是"起点" —— CurrentSpreadAngle 永远不会低于 当前姿态的 Base。所以 SpreadAngle_Standing = 0.35 意味着"站定静止时，锥角最小就是 0.35°"。
③ 姿态是瞬时的 —— 蹲下 / 起跳立刻换一组参数（不插值），与后坐力姿态倍率的口径一致。 只有"站定 ↔ 跑动"这一路是连续的（走 SpreadTransitionRate_StandingStill 的 FInterpTo）。

姿态 → 参数组对照

姿态来源（代码判定）取哪一组参数什么时候会发生
IsFalling()*_JumpingOrFalling 跳跃 / 下落中。优先级最高——蹲着跳算空中不算蹲
IsCrouching()*_Crouching蹲伏
其余*_Standing 站立（含跑动；跑动额外乘 SpreadMovementMultiplier）

10 · 回正扣减压枪量（终版 · 2026-09-21 二次修正）

10.1 一句话：回正把偏移收敛到「你自己压下去的量」

以前：开枪把准星顶高 10°，你往下压 4° 把它拉回目标 —— 松手回正时偏移回到 0， 那 4° 被还回去了，准星比目标低了 4°，你得再抬一次。

现在：回正终止值就是你本梭累计压的枪。 屏幕视角 = ControlRotation（含你的压枪） + 后坐力偏移， 你压 P 度 ⇒ Ctrl = −P，而偏移也收敛到 P ⇒ 屏幕 = −P + P = 0 ⇒ 精确回到开枪前。不压枪就回满、压多少就停多少。

垂直轴默认生效，水平轴默认不参与（2026-09-21 起）。Pitch 与 Yaw 共用同一条公式， 但 bCompensationAwareRecoveryYaw 默认 false —— 水平方向没有"压枪"，你的水平鼠标是转身。理由见 10.6。

已删除两个字段（2026-09-21） RecoilReturnRatio（残留比例缩放）与 RecoilCompensationMinResidualRatio（残留地板） 已按要求删除，不再出现在资产上。
为什么必须让峰值退出：只要终止值跟峰值挂钩，屏幕就必然偏离开枪前 —— 峰值 × Ratio − P 会让认真压枪直接归零（旧式问题）； 峰值 − P 会让屏幕 = Ctrl(−P) + (峰值 − P) = 峰值 − 2P（看地板）。 现行式让峰值彻底不参与，屏幕恒回零。

10.2 公式（想手算就照这个）

回正终止值 = 本梭累计压枪量        ← 就这一行，峰值不参与、无 clamp、无 Ratio、无地板

不压枪 ⇒ 终止值 0 ⇒ 偏移回满；压 P 度 ⇒ 终止值 P ⇒ 屏幕回零。抵扣量有两个串联闸门： bCompensationAwareRecovery（总开关）+ 各轴开关，两把都开才扣。 默认：总开关开、Yaw 关。关掉总开关 ⇒ 终止值恒 0 ⇒ 偏移完全回满。

10.3 场景对照（大祥老师口径）

起始 POV = 0，K = 本轮峰值（枪把镜头抬高多少），P = 你压枪的位移（向下为正）。 终止值 = P，回正量 = K − P：

场景KP偏移终止值屏幕 POV回正量 K−P
完全没压枪10°0°0°0°（回零）10°（回满）
压了一半10°5°5°0°5° ← 老师原例
压满10°10°10°0°0°
压过头5°10°10°0°−5°（偏移反而上升，见 10.6 末尾）

自动化用例 Lyra.Recoil.Compensation.UserContractScenarios 锁死三条不变量： ① 终止值 == P；② −P + 终止值 == 0；③ K − 终止值 == 期望回正量。 （K 靠发数凑：每发 0.5°，K=5 用 10 发、K=10 用 20 发；P 靠 SamplePlayerAim 喂负值。）

⚠️ 更正：旧文档里的 A / B / C / D 四场景表是误记 以前本文列过「A(没压住 5°)=+5 / B(压过头 5°)=−5 / C(压过头 10°)=−10 / D(没压住 10°)=+10」， 并把它标成"权威验收口径" —— 那是文档整理者自行推演的场景，不是大祥老师的口径。
大祥老师真实的口径只有两条：① 完全不压枪 ⇒ 自动回到开枪前（回零）； ② 后坐力整体上抬 10°、只往下压 5° ⇒ 回正只回 5 度。
现行口径下上表四行屏幕都收敛到 0，差异体现在「回正量 = K − P」而不是「屏幕停在哪」。

10.4 两个开关（都在资产上，Recoil | Recovery 分类）

开关默认管什么
bCompensationAwareRecovery开总开关：回正扣不扣压枪量
bCompensationAwareRecoveryYaw关水平轴开关：Yaw 要不要也扣

两个都是独立的。改完 PIE 立即生效，不用重编。

  • 关掉总开关 → 终止值恒 0 ⇒ 偏移完全回满（玩家压的枪被"还回去"），用于 A/B 对照。
  • 打开水平轴开关 → 水平轴也收敛到水平位移量（2026-09-21 起这个开关才真的可用， 修掉了"打开也不生效"的硬编码）。
  • 没压枪时终止值 = 0，与"完全回满"一致 —— 所以"我没压枪也觉得准星飘了"不是这套逻辑引起的。
  • 压枪量本身在开关关闭时照常显示，只是不参与回正。

10.5 看数：面板多出来的那一行

Lyra.Recoil.Debug 1
  PushComp P=0.000 Y=0.000   CoverUsed P=0.000 Y=0.000   Applied=N   AimNow=(0.00, 0.00)
字段是什么
PushComp P / Y实时压枪量：相对本轮第一发，你把准星往后坐力反方向拉了多少度。往下压 / 往左拉为正
CoverUsed P / Y进入回正时冻结的抵扣额度 —— 回正目标真正用的是它。与本梭累计压枪量同源
Applied"本梭内是否已经进入过至少一次回正"（Y / N）—— 纯观测位（2026-09-22 起）。现行 min() 公式下重复冻结无害，它不再控制任何行为，只供看板/测试断言用
AimNow最近一次采样到的 ControlRotation，真值基准
四条容易被当成 bug 的行为（都是刻意的） ① 中途回正不会把抵扣放大。插值模式下RecoveryDelay可能撞上射速间隔， 触发多次"中途中止回正"；旧增量公式每次都扣一遍（cover=4 时实测 Δ=−5.067 而非 −4）。 现行 min() 绝对公式下每次回正从同一对锚点独立算出，重复冻结天然无害（2026-09-22 起短路已删， Applied 只做观测）。
② 压枪量只在"开始回正"那一刻冻结。RecoveryDelay 之内继续压的枪算数； 回正开始之后再动鼠标不会改变落点。
③ 连续多轮开火时，压枪量会一轮一轮垒进残留偏移，顶到 MaxVerticalKick / MaxHorizontalKick 后停住（不再增长）。 观感上不可见（准星就是显示层），但你的鼠标会一轮比一轮多压一点。 觉得不舒服就关掉总开关 bCompensationAwareRecovery。
④ 压过头（P > K）时偏移会升到峰值之上。屏幕口径仍自洽（−P + P = 0）， 但插值链的 Drop 段表现为相机向上补一段（回正量为负）。这是"照现行口径字面执行"的结果， 实战里 P ≈ K，属少数情况。详见 10.6 末尾。
2026-09-21 修掉的一个真 bug：Drop 段偏移冻结后瞬跳 插值链的 Drop 段原先读的是 Applied ? 0 : 累计压枪量，而 Applied 在 Settle→Drop 切换处就已置 Y ⇒ 整个 Drop 段目标恒为 0， 偏移冻结在钳制上限 15.000 共 23 帧，收官那帧才一跳到终值 （屏幕 +2.75 → −8.30）。用 Lyra.Recoil.Trace 1 抓到。
现在 Drop 段直接读冻结快照 CoverUsed，与收官计算同源 ⇒ 平滑收敛、不再跳。

10.6 为什么 Yaw 被摘出来了（2026-09-21 修订）

原因就是「系统分不出你在压后坐力还是在追人」—— 但它对两轴的影响完全不同：

轴峰值上限实机里会发生什么
Pitch4.0°（S 型）要"认真压枪"才撞得到
Yaw2.0°转身超过 2° 随时发生 ⇒ 水平回正长期恒为 0

所以水平轴改成默认不抵扣：PushComp Y 照常显示，只是不算进回正。 想退回「两轴同规则」就打开 bCompensationAwareRecoveryYaw（现在真的会生效）。

压过头 = 偏移会高于峰值（预期，但值得知道） 现行口径是字面「终止值 = 累计压枪量」，没有对 P 设上限。
你压的比峰值多（P > K）时：屏幕照样回到开枪前（−P + P = 0 ✅）， 但偏移会从"回弹终点"向上补到 P（回正量 K − P < 0）。 这与旧文档写的"压过头 ⇒ 低于起枪点 ⇒ 看地板"不是同一件事 —— 后者是公式方向错导致的 bug，已修。
若觉得这段"向上补"观感不好，可选：① 给 Cover 取 min(Cover, Peak)； ② 压过头时走"偏移不高于峰值"的退化路径。（待拍板，当前按现状锁死。）
