“六自由度”指枪的三个旋转轴和三个平移轴；这里是相对持枪基姿态的视觉偏移，不是物理模拟，也不是再增加一次相机后坐。

2. 两项目实查结果

2.1 参考项目：可借用的实现思路

参考包是蓝图资源项目。AC_ProceduralWeaponAnimationSystem 包含 OnFired、F_ProceduralRecoil、F_ProceduralRecoilSpring、F_ProceduralCameraRecoil、F_CombinedProcedural 等函数名；S_ProceduralRecoilStats_Recoil 中可见后退、上抬、横移、Pitch/Yaw/Roll 的范围和倍率，另有位置、旋转独立的弹簧、回位和钳制结构。ABP_FPChar 使用 Modify Bone 与 FABRIK。它还提供 EUW_ProceduralEditor、WB_PE_XYZ、WB_PE_FireRate 等编辑器调试资源。

这些信息来自资源文件中的类型、函数、变量及动画节点。由于蓝图是二进制，本次没有逐条导出节点连线；因此下面的算法是针对 TPSGunsDemo 的设计方案，不是宣称参考项目采用了完全相同的数学公式。参考项目第一人称相机、手臂骨架和射击角色蓝图不应原样接管 Lyra 流程。

3. 目标架构

一次成功开火（GA CommitAbility）
  └─ ULyraRangedWeaponInstance::AddRecoil()
      ├─ FRecoilRuntimeState::ApplyShot()       现有：镜头 / 弹道 / Roll / 历史
      └─ VisualRecoil.ApplyShot(ShotEvent)      新增：枪体六自由度脉冲
                         │
每帧 WeaponInstance::Tick() ─ VisualRecoil.Advance(DeltaTime)
                         └─ FWeaponVisualRecoilPose {LocCm, RotDeg, Alpha, ShotSerial}
                                      │
                      角色动画层（右手/ik_hand_gun）
                                      │
             weapon_r 挂载的 B_Rifle 随右手运动
                                      │
                     左手 IK 追枪的前握把目标

视觉层拆成两个频段：脉冲层表达枪的机械撞击与回弹，对齐层轻微参考镜头的实际 Pitch/Yaw/Roll 输出。前者决定手感形状，后者保证枪与镜头观感一致。两者在动画输入处组合，不能复用相机累计值作为整个枪体位移，否则长连发会把枪抬离持枪姿势。

职责边界

  • ULyraRecoilProfile：存每枪的视觉参数；旧字段语义不变。
  • FWeaponVisualRecoilState：纯数学状态，输入一次 ShotEvent，输出六自由度偏移；不访问骨架或 Actor。
  • ULyraRangedWeaponInstance：拥有该状态，开火、每帧推进、切枪归零。
  • 动画蓝图 / 可选的薄 C++ 桥：读取结构快照、换算到骨骼空间、处理 IK。
  • 武器 Actor：继续负责模型、枪口与效果；不作为弹道算法的输入。

4. 数据与坐标契约

建议在 ULyraRecoilProfile 新增 Recoil|WeaponVisual 分类，最初只为正在使用的两把步枪配置；手枪和霰弹枪待管线稳定后扩展。不要把视觉参数混入现有弹道或相机字段。

参数组建议字段单位与用途
开关与强度bEnableWeaponVisualRecoil、VisualScale、ADSVisualScale无量纲；支持单枪关闭与瞄准倍率。
六轴脉冲KickPitch/Yaw/Roll；KickBack/Up/Side前三项度，后三项厘米；每发的有符号目标脉冲。
与实际后座绑定PitchFromShotKick、YawFromShotKick、RollFromCameraRoll、AlignmentPitch/Yaw基于本发实际垂直/水平 Kick 与镜头输出的映射系数。
形状与回位AttackStiffness/Damping/Mass、ReturnStiffness/Damping/Mass 或 Attack/ReturnDuration位置、旋转最好各自独立；首版可用两组三维弹簧参数。
钳制MaxAbsRotation、MaxAbsTranslation、MaxAlignment防止连射偏移和 IK 拉伸失控。
姿态HipMultiplier、ADSMultiplier、CrouchMultiplier、AirMultiplier能先借用现有 ComputeRecoilPoseMultiplier()；如美术手感需要再独立。
调试与运动学PivotOffset、RightGripOffset、LeftGripSocket、LODThreshold每枪模型/握把校准数据，不参与射击算法。
坐标先定再调参：UE 局部空间通常 X 向前、Y 向右、Z 向上；但 weapon_r 插槽及步枪资源的实际轴向必须在编辑器里画三轴确认。运行时输出统一约定为“角色/持枪基座局部空间的厘米与度”。后退/上抬/横移是设计语义，映射到具体 FVector 分量时由每枪的轴配置或校准矩阵决定，不能凭名称硬编码正负号。

建议对每个资产保留 NeutralTransform，每帧由“当前基姿态 + 视觉偏移”计算最终姿态。禁止对上一帧 Actor 相对变换继续累加，避免切枪、蒙太奇或帧率变化造成漂移。

5. 六自由度运动算法

5.1 本发输入

定义轻量 FWeaponVisualShotEvent：ShotSerial、ShotIndex、实际 VerticalKick/HorizontalKick、PoseMultiplier、AimingAlpha、CameraRollSample 和武器预设指针。每发只生成一次，使用现有后座同一个索引与随机种子。不要再随机抽一个独立的左右方向；允许小幅可复现扰动，但默认同一发向左的弹道，枪的 Yaw/横移也向相应方向。

ShotPitch = PitchBase + PitchFromShotKick × VerticalKick
ShotYaw   = YawBase   + YawFromShotKick   × HorizontalKick
ShotRoll  = RollBase  + RollFromShotYaw   × ShotYaw
ShotBack  = BackBase  × ShotStrength
ShotUp    = UpBase    × ShotStrength
ShotSide  = SideBase  × sign(HorizontalKick) × ShotStrength
ShotStrength = VisualScale × lerp(HipMultiplier, ADSMultiplier, AimingAlpha)
               × PoseMultiplier

以上是可调的映射关系，不是固定数值。开火时把六轴脉冲注入目标或速度，按轴钳制；位置与旋转分别推进弹簧。连续开火允许小幅叠加，但应该保留每发的可感知冲击，不把镜头长连发的 4° 累积直接等比例复制到枪上。

5.2 两段动态

  1. 撞击阶段：高响应，把枪迅速向后、向上并偏转；可以用速度冲量驱动弹簧，或使用 0→1 的 Attack 曲线。
  2. 回位阶段：目标回到零偏移，阻尼略低以保留少量惯性。位置和旋转可不同速度；在下一发到来前允许尚未完全归零。
  3. 停火与状态切换：正常停火继续自然回位；换枪、死亡、装备中断时清空或短时淡出；重装/近战蒙太奇期间按权重压低视觉通道。
struct FWeaponVisualRecoilPose {
    FVector LocationCm;      // 已钳制的视觉位移
    FRotator RotationDeg;    // 已钳制的视觉角度
    float Alpha;             // 蒙太奇/装备/LOD 混合权重
    uint32 ShotSerial;       // 防止重复触发
};

// 伪代码：定步长推进可复现弹簧，最终只向动画层公开快照
OnCommittedShot(Event) { TargetOrVelocity += MapShotToSixAxes(Event); Clamp(); }
Tick(dt) { for (substep : FixedSteps(dt)) IntegrateSpring(substep); PublishPose(); }

数值实现可借鉴参考项目的位置/旋转分离弹簧，但建议用 UE C++ 纯状态实现并加固定子步长，和当前相机 Interpolated 单发模型的帧率稳定策略保持一致。采样 30、60、120 FPS 时，峰值和归零时间应接近。

6. 与现有镜头匹配

当前镜头后座由 FRecoilRuntimeState 的 CameraOffsetPitch/Yaw 与独立 RollShake 输出，UCameraModifier_WeaponRecoil 只修改显示相机。枪体应通过同发输入 + 弱对齐与它协调，而不是把枪体动画直接复制到相机。

信号建议用途限制
本发 Vertical/Horizontal Kick决定枪体 Pitch/Yaw 方向与相对强度与本发实际射击结果共享索引；勿从总累计值反推“本发”。
CameraOffsetPitch/Yaw低频、弱幅度的视线对齐项单独钳制，避免连发时枪体永久高抬；这不是枪的机械冲量。
RollShake.CurrentRoll枪体 Roll 的轻微相关运动镜头 Roll 有独立包络；枪体 Roll 仍需自己的回位。
玩家 ControlRotation继续让原有瞄准层处理玩家输入视觉后座不写 ControlRotation，也不额外修改弹道。

验收时用同一发的曲线叠图看三个时刻：枪体撞击峰值应与镜头 Lift 相近；枪体一般比镜头更快回到握枪基姿；连发时枪体不越过肘部可达范围。最终符号、比例和延迟以靶场录屏校准，不能凭参数名确定。

7. 骨骼与双手 IK：主方案

推荐“右手驱枪，左手追枪”。当前 WID_Rifle 把 B_Rifle 挂到角色 weapon_r。若直接对 B_Rifle 根组件做六轴变换，右手仍停在原地。应先让角色持枪手/其 IK 目标运动，武器跟随插槽，再让左手贴到移动后的前握把。

7.1 建议的动画顺序

  1. 现有 Locomotion、AimOffset、上身姿态、开火/重装蒙太奇完成基本持枪姿。
  2. 在现有 SkeletalControlsLayer 的合适位置，给右手目标或 ik_hand_gun 增加程序化六轴偏移；使用 TwoBoneIK/Control Rig 解右臂，必要时给锁骨/胸椎少量分摊角度。
  3. 武器继续随 weapon_r 插槽移动。对步枪前握把计算左手目标，以现有 LeftHandIK、VB IK_Hand_L_weaponSpace 或相应 TwoBoneIK 解左臂。
  4. 在最终姿态后做手腕/手指微调，保持握把接触；下半身、脚部 IK 不参与此通道。

不能形成循环依赖：“枪挂右手 → 右手 IK 目标从本帧枪世界变换读取 → 枪再挂右手”是环。右手目标必须由基姿态和纯视觉偏移算出；左手可以追随已经求出的枪。动画线程里也不要直接查询正在变化的武器 Actor：按现有 ABP_Mannequin_Base 的线程安全注释，先在安全时机复制快照，通过 Property Access/AnimInstance 变量读取。

7.2 首个原型与正式接入

首个原型可以只给 ik_hand_gun / 持枪手增加 Pitch 与后退，确认枪和右手连动，再加 Yaw/Roll/上抬/横移和左手 IK。正式接入应复用或扩展 ABP_ItemAnimLayersBase 的 SkeletalControlsLayer，由 ABP_RifleAnimLayers 实例配置步枪握把。不要修改公共基础层到让手枪、霰弹枪也无条件运行步枪参数。

在编辑器里检查 HandIKRetargeting 与 TwoBoneIK 的当前顺序：若后置的 IK 会抵消新加的右手偏移，应把视觉目标注入 IK 目标而不是在 IK 后直接改手骨。RaiseWeaponAfterFiringWhenCrouched 是现有开火相关姿态逻辑，需要检查是否与新增上抬重复。

7.3 更大改造的备选

若未来需要“枪作为主物体、双手完全跟枪”及复杂装填动作，可建立独立的胸前 WeaponPosePivot，让枪挂 Pivot，双手 IK 分别追握把。它会改变现有 weapon_r、装备蒙太奇、枪口效果与手部动画契约，适合作为后续重构，不作为第一阶段方案。

8. Lyra 代码与资源接入

位置拟修改内容注意事项

LyraGameplayAbility_RangedWeapon.cpp原则上不新增第二个触发点现有 AddRecoil() 在成功 CommitAbility 后，正好是每发事件。
LyraAnimInstance 或项目专用子类缓存当前武器的 FWeaponVisualRecoilPose，暴露给动画蓝图在游戏线程取对象；动画图只读快照。确认武器实例查询路径与卸枪空值处理。
ABP_ItemAnimLayersBase / ABP_RifleAnimLayers程序化右手目标、上身少量分摊、左手跟枪；按枪型混合保留已有 AimOffset、蒙太奇、HandIKRetargeting 与足部 Control Rig。
B_Rifle / 步枪骨架校准右握把、左前握把和枪口插槽；必要时加 LeftHandGrip socket握把 socket 放在实际枪模型，左手目标以稳定的武器局部空间表示。

事件顺序：现有能力先完成目标数据/射击，再提交消耗，随后调用 AddRecoil()。枪体后座在该调用里触发；这样空仓、取消或提交失败不会出现“枪动了但没开火”。枪口特效可以继续从武器模型插槽发出，但弹道方向仍由现有 Ability 计算，不能改为使用视觉后座后的枪管朝向。

生命周期：OnEquipped() 与 OnUnequipped() 已在 LyraRangedWeaponInstance.cpp:147–195 处理相机后座重置/释放。视觉状态也要同步归零或淡出。重装、近战、切换武器和死亡时明确 Alpha 规则，避免后座留在新动画上。

9. 参考项目资源：哪些能搬运

资源判断处理方式
S_ProceduralRecoil*、预设 DA_WPP_*适合借字段与调参起点，不建议作为正式数据层直接使用TPSGunsDemo 已有 ULyraRecoilProfile。手工映射 Pitch/Yaw/Roll、KickBack/Up/Side、弹簧和 Clamp，防止双份配置。
AC_ProceduralWeaponAnimationSystem不直接接入主流程它同时管第一人称瞄准、相机、移动等，会与现有 Lyra 后座/动画系统冲突；参考函数结构即可。
ABP_FPChar、第一人称姿势不直接搬到 TPS 人物骨架、相机、全身动画层不同；改为在现有 Lyra Linked Layers 中实现。
EUW_ProceduralEditor、WB_PE_XYZ、WB_PE_Bar、WB_PE_FireRate、BPI_ProceduralEditor可迁移为编辑器 UI 原型用 UE 的 Migrate 带依赖复制到隔离目录。布局、XYZ 输入、按钮可复用；原有接口绑定的是参考组件，必须换成 TPS 的 Profile/VisualState 适配器。确认依赖和编译后再决定是否保留。
参考项目的枪模型与演示 BP仅适合对照当前项目已有 B_Rifle、SK_Rifle 及装备资产；不需要替换。
参考 PWAS.uproject 当前 EngineAssociation 为 5.8，项目文件夹名却带 5.1/5.7；其中名为 ProceduralWeaponAnimationSystem 的插件条目被禁用。迁移 UI 前，应在一份项目副本中用同一引擎版本执行 Migrate、编译并检查缺失引用。所谓“可搬运”指资源布局和控件可搬，不表示复制后会自动连接 Lyra 状态。

10. 调试工具与 Gun Kick 面板

优先扩展项目现有 Lyra.Recoil.Debug、CSV 和调参 HTML，而非再建一套并行调试入口。可以把参考项目 EUW_ProceduralEditor 的 XYZ 控件搬作编辑器调参外壳，但数据读写统一走 TPS 的 ULyraRecoilProfile。这样枪体参数、镜头参数与真实弹道曲线能并排看。

面板页应显示/操作
Live当前武器、ShotSerial、ADS Alpha、枪体 6 轴当前值/目标值、相机 Pitch/Yaw/Roll、IK Alpha、当前动画状态。
Gun Kick6 轴每发脉冲、位置/旋转弹簧、各轴 Clamp、左右手握把校准；单发/3 发/持续开火预览。
Compare同一时间轴叠加 CameraOffsetPitch/Yaw、WeaponVisual Pitch/Yaw/Roll/XYZ、ShotIndex；支持 30/60/120 FPS 数据对比。
Ablation分别关闭“镜头”“枪体”“左手 IK”“对齐项”，便于找出重叠或迟滞来源。

建议追加 Lyra.Recoil.Visual 0/1、Lyra.Recoil.VisualScale、Lyra.Recoil.VisualDebug 等 CVar，并在现有 CSV 每帧导出 6 轴和 IK 权重。预设热重载可沿用 LyraRangedWeaponInstance::ReloadRecoilProfile()，无需创造第二套资产热加载。

建议的可重复测试矩阵

  • 每枪：单发、点射、长连发，腰射/ADS，站立/蹲下/移动/空中。
  • 中断：射击中换枪、射击中重装、空仓扣扳机、死亡、暂停再恢复。
  • 画面：近墙、肩后相机切侧、不同 FOV、不同角色体型、近距离观察握把和枪口。
  • 数值：连续开火有上限、停止后归零、同种子同事件产生相同六轴序列、帧率差不造成明显峰值变化。
  • 回归：现有弹道 Golden、散布、镜头 Roll、压枪补偿与 Docs/Recoil/Tools/run-all-checks.ps1 继续通过。

建议单发初始调参顺序：先只开 Back 与 Pitch → 调 Attack/Return → 再加 Up → 用实际水平 Kick 接 Yaw/Side → 最后少量 Roll 与镜头弱对齐。一次只改一个轴，单发满意后再检查连发。参数大小应由实际模型、FOV 与 IK 可达范围决定，此处不硬填通用厘米/角度值。

12. 风险、决策与待核实项

问题影响处理
动画层 IK 顺序未逐节点验证后置 IK 可能把右手后座抵消V0 在编辑器打开 ABP_ItemAnimLayersBase 与 ABP_RifleAnimLayers，记下节点顺序和使用空间；以实际节点为准落位。
枪/骨架轴不统一Yaw、Roll、后退方向可能反对 weapon_r、hand_r、步枪模型画三轴；用每枪校准变换，不在核心算法写死。
同一事件重复消费枪体连跳或空枪有后座只由成功 CommitAbility 后的 AddRecoil() 发事件；用 ShotSerial 去重。
视觉枪口与真实命中分离近墙时视觉弹道看似不对齐保留现有射击方向；单独核对近距离枪口 VFX/遮挡和准星，必要时调效果而非改后座算法。
叠加现有开火动画蹲姿额外上抬、蒙太奇与枪体后座翻倍检查 RaiseWeaponAfterFiringWhenCrouched、武器 Fire 事件和动画槽；调 Alpha 或移除重复表现。
视觉参数塞入旧相机字段长线调参相互牵连视觉参数独立分组；共享本发事件和姿态倍率，状态输出分开。

本方案按仓库当前“单机 Demo”约束设计。若未来恢复联机，需另行设计远端开火事件、预测和视觉状态同步；不要把当前本地 Pose 快照直接复制为权威射击状态。
